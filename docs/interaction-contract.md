# 课程展示与交互约定

## 专业边界

- 课程正文、实验数据与面试短答采用一致的定义和例子；不同例子必须明确标明。
- 标明语言、单位、位宽、执行顺序、容量及其他影响结论的条件。
- 教学模拟、参考输出和真实运行分别标识。模拟不代表任意输入下的真实硬件或运行时行为。
- 同一个概念在不同语言中的保证不能直接互换。语言特定实验要给出适用的语言规则。
- 错误示例区分编译错误、运行错误、未定义行为和未满足契约，不把未定义行为描述成确定输出。

## 机制与操作

实验内部的形式由机制决定，而不是由课程数量决定：

| 机制                 | 展示重点                                     |
| -------------------- | -------------------------------------------- |
| 地址、引用和生命周期 | 存储位置、指向关系、别名、存活及悬空状态     |
| 算法                 | 当前位置、候选范围、依赖、比较结果与终止条件 |
| 调度与资源           | 运行位置、队列、容量、等待原因及拒绝条件     |
| 网络与 I/O           | 请求与返回、分层、缓冲、缓存和可观察的时序   |
| 数据库与版本         | 记录、索引、提交边界、快照和可见版本         |
| 工程与面试           | 可比较的实现、证据、失败分支和具体表达       |

- 输入后应能看见哪些状态改变、哪些保持不变。重要的状态不能只藏在日志里。
- 单步控制只适用于真实存在的迭代或状态转换；不能用文字翻页代替机制操作。
- 非法输入应保留原文并说明约束，不静默转成另一个值，不让实验崩溃。
- 拒绝操作要显示原因和是否修改了原状态。
- 重置恢复可操作的初始输入、状态和记录；无效输入后的重置也应有效。
- 完成状态来自模型结果，不来自动画播完或固定点击次数。

## 视觉与动效

- 共用标题、控件和反馈规则，保留场景自己的结构。引用图、依赖网格和协议轨迹不应变成同一模板。
- 选中、可操作、运行、完成和错误状态同时通过文字、图标或结构表达，不能只靠颜色。
- 动效表现移动、关系变化和读数变化，不延迟真实状态更新，也不制造不存在的进度。
- 连续操作可以中断旧动效；切换课程、重置和卸载后不能遗留定时器或任务。
- 系统减少动态效果偏好和站点开关同时生效，关闭动效后仍保留完整的状态信息。
- 舞台尺寸和控件尺寸应稳定；长文本换行或在专用容器滚动，不撑宽页面。

## 阅读与代码

- 阅读定位条只表示当前位置，阅读状态由明确的完成操作记录。
- 选择题验证判断，口述草稿用于表达与对照；文本长度不代表答案正确。
- 首次通过才增加经验值，重复练习保留记录但不重复计分。
- 多语言示例保留对应语言的适用条件和结果，不把参考代码展示伪装成编译或运行。
- 只读代码的横向滚动归一个容器管理。换行、折叠、复制和方向控制均可用键盘操作。
- 编辑型运行器区分加载、执行、结束、报错与停止。代码修改后，旧结果要明确标记。
- 输出限制和失败提示不能被动效或视觉简化隐藏。

## 验证范围

维护时检查每个实验类型的首访、正常操作、明显错误、重置、关键状态和减少动效；共享改动还需检查课程导航、阅读、自测、存档和代码滚动。

构建、模型测试、浏览器检查与线上版本确认分别记录。通过默认示例或抽查，不等于穷举全部输入与操作顺序。
