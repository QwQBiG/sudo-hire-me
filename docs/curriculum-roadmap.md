# 200 节面试课程路线图

目标是至少 200 节可独立学习的核心课程，服务于从基础开始的综合技术面试准备。这里的“节”不是一道题或一个标题：每节都要有准确的面试短答、从零可跟上的解释、可手算或可追踪的例子、边界与常见误解，以及与概念相配的练习。考研 408 的严谨性用于核对组成、数据结构、操作系统和网络概念，不把整套 408 大纲机械搬进面试课。已发布的 slug 不重命名，避免丢失学习记录。

| --- | ---: | --- |

## 学习顺序

1. **第一阶段：基础问题。** 先补程序、函数、参数、数组、指针、类与对象、封装、继承、多态，再接位/字节、复杂度、进程线程、网络分层、SQL。能用自己的话回答“是什么、为什么、举例”。
2. **第二阶段：常见手算与代码题。** 做顺序/二分查找、排序、树与图、子网、地址转换、调度、事务和 SQL 查询。每题写出中间状态、边界和复杂度。
3. **第三阶段：机制与反例。** 深入缓存、同步、内存、TCP、索引、隔离与并发。面试短答以条件和限制收口，避免背出脱离前提的绝对结论。
4. **第四阶段：工程与项目。** 把测试、定位、构建、性能与真实项目贡献连到技术选择上，练习清晰说明证据和个人职责。
5. **回顾与迁移。** 逐课复核术语、先修、代码、例题和互动；较少见或明确依赖岗位的内容作为选修，不挤占基础主线。

选题参考 [Amazon 的软件开发面试主题](https://amazon.jobs/content/en-gb/how-we-hire/interview-prep/software-development-topics)、[Microsoft 的技术面试准备说明](https://careers.microsoft.com/v2/global/en/hiring-tips/technical-interviewing)和 [ACM/IEEE-CS/AAAI CS2023 的知识领域](https://csed.acm.org/knowledge-areas/)。这些来源只说明准备范围；具体岗位和面试形式仍以招聘方通知为准，不把一家公司公开的清单当作所有公司的统一题库。

## 课程体验

一个知识点只选择有助于理解它的主要交互，不使用统一步骤卡片套所有页面：

| 知识形态 | 适合的呈现 |
| --- | --- |
| 状态随操作变化 | 真实可操作的状态机，例如窗口、锁和页替换 |
| 同一输入有不同算法路径 | 并排轨道与逐轮对照，例如排序和图搜索 |
| 需要算出数值 | 可改参数的算例，保留每一步和单位 |
| 代码行为容易误判 | 可运行代码、实际输出和错误路径 |
| 错误源于条件或时序 | 故障现场、输入证据与修复前后对照 |
| 需要记住关系 | 小图、表和可回放的因果链，而不是装饰动画 |

互动是解释的补充。Markdown 中必须有完整推导，GitHub 上不打开网站也能学；网站可提供更多操纵、回放和即时反馈。每节保留一段能在面试中说清的短答，但不让短答替代正文。

## 内容质量门槛

- 先交代模型、输入、单位和前提，再给公式或结论；明确典型实现与所有实现的区别。
- 至少有一个可核对的具体例子；涉及动态过程时展示中间状态和结果。
- 术语首次出现给英文全称与常见缩写；不逐字翻译普通词。
- 一题一课，选择题测试理解中的真实误区；解析说明为什么错。
- 实验的假设和限制写在界面及正文中；不能把教学模拟伪装成完整协议或真实运行。
- 外部事实优先引用标准、官方文档或公开教材；对版本与实现相关的行为标出条件。
- 发布时核对 Markdown、网站生成结果、直接相关的模型测试和关键窄屏路径；大批量内容不为通过数量而复制模板。
