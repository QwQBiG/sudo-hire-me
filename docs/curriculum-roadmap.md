# 面试知识点路线图

目标是至少 200 节可独立学习的课程。这里的“节”不是一道题或一个标题：每节都要有准确的面试短答、从零可跟上的解释、可手算的例子、边界与常见误解，以及与概念相配的练习。现有课程仍按先修关系进入新目录；已发布的 slug 不重命名，避免丢失学习记录。

## 范围与配额

| 方向 | 目标课数 | 从基础到进阶的范围 |
| --- | ---: | --- |
| 计算机组成与表示 | 20 | 数制、补码、浮点、字节序、对齐、CPU、指令、缓存、存储层次、I/O |
| 数据结构与算法 | 35 | 复杂度、线性结构、排序查找、树、堆、图、字符串、动态规划与常用证明 |
| 操作系统 | 25 | 进线程、调度、同步、死锁、内存、文件系统、系统调用与 I/O |
| 计算机网络 | 25 | 分层、寻址、子网、ARP、TCP/UDP、HTTP、TLS、DNS 与故障定位 |
| 数据库 | 25 | SQL、约束、索引、事务、隔离、执行计划、日志、复制和常见查询问题 |
| 编程语言与运行时 | 20 | 类型和值、内存管理、异常、并发模型、JavaScript 与 Rust 的关键机制 |
| Web 与服务端 | 20 | 浏览器、请求链路、认证、缓存、API、性能、可靠性与安全边界 |
| 工程实践 | 15 | Git、测试、调试、构建、持续集成、日志、监控、部署与排障 |
| 分布式基础 | 10 | 一致性、复制、幂等、重试、消息、限流、熔断和故障恢复 |
| 项目表达 | 5 | 问题背景、个人贡献、技术取舍、指标证据与追问应对 |
| **合计** | **200** | 以面试需要的解释与判断为边界，不机械讲完一整套教材 |

这些配额是课程规划，不是已经发布的数量。实际发布数以 `content/lessons/` 中通过内容校验的独立 Markdown 文件为准；不把路线图条目计作课程。

## 推进顺序

1. **基础闭环，约 50 节。** 先补齐位运算、函数调用、堆与图、页替换、IPv4 子网、数据库约束和常见 SQL 错误。每节能独立回答一个基础追问。
2. **面试高频，约 80 节。** 扩展 CPU/缓存、排序查找、同步、TCP、HTTP、事务、JavaScript 运行机制；相近问题互相链接，但不合并成题库页。
3. **机制与权衡，约 120 节。** 补足边界条件、反例、复杂度、失效路径；让读者能解释“为什么”，而非只背结论。
4. **工程与项目，约 160 节。** 引入调试、部署、故障定位和真实项目表达，使基础知识能转成可验证的决策。
5. **完整覆盖，至少 200 节。** 补齐较低频但常见的基础面试点，逐节复核术语、先修、例题与互动的正确性。

## 课程体验

一个知识点只选择有助于理解它的主要交互，不使用统一步骤卡片套所有页面：

| 知识形态 | 适合的呈现 |
| --- | --- |
| 状态随操作变化 | 真实可操作的状态机，例如窗口、锁和页替换 |
| 同一输入有不同算法路径 | 并排轨道与逐轮对照，例如排序和图搜索 |
| 需要算出数值 | 可改参数的算例，保留每一步和单位 |
| 代码行为容易误判 | 可运行代码、实际输出和错误路径 |
| 错误源于条件或时序 | 故障现场、输入证据与修复前后对照 |
| 需要记住关系 | 小图、表和可回放的因果链，而不是装饰动画 |

互动是解释的补充。Markdown 中必须有完整推导，GitHub 上不打开网站也能学；网站可提供更多操纵、回放和即时反馈。每节保留一段能在面试中说清的短答，但不让短答替代正文。

## 内容质量门槛

- 先交代模型、输入、单位和前提，再给公式或结论；明确典型实现与所有实现的区别。
- 至少有一个可核对的具体例子；涉及动态过程时展示中间状态和结果。
- 术语首次出现给英文全称与常见缩写；不逐字翻译普通词。
- 一题一课，选择题测试理解中的真实误区；解析说明为什么错。
- 实验的假设和限制写在界面及正文中；不能把教学模拟伪装成完整协议或真实运行。
- 外部事实优先引用标准、官方文档或公开教材；对版本与实现相关的行为标出条件。
- 发布时核对 Markdown、网站生成结果、直接相关的模型测试和关键窄屏路径；大批量内容不为通过数量而复制模板。
