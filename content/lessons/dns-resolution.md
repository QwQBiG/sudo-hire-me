# DNS 查询与缓存

## 面试回答

域名系统（Domain Name System，DNS）是按域名层次组织的分布式命名系统，常用于查询域名对应的网际协议（Internet Protocol，IP）地址，也保存其他类型记录。客户端通常把请求交给递归解析器，解析器先查缓存，必要时沿委派关系找到权威服务器，再返回结果。缓存按记录的生存时间管理。DNS 可以使用用户数据报协议（User Datagram Protocol，UDP）和传输控制协议（Transmission Control Protocol，TCP），不能把它等同于“只走 UDP 的域名转地址接口”，也不能把解析成功等同于网页已经下载成功。

## 从零理解名字的层次

完整名字 `www.example.com.` 最右侧的点表示根。自右向左可以看到根、`com`、`example` 和 `www` 这些层次。

管理一个区域的服务器不需要亲自保存整个互联网的所有名字。它可以通过委派（Delegation）指出某个下级区域由哪些服务器负责。

| 角色 | 英文名称 | 主要责任 |
| --- | --- | --- |
| 客户端的存根解析器 | Stub Resolver | 向配置的解析服务发出查询 |
| 递归解析器 | Recursive Resolver | 为客户端查询结果，跟进委派并维护缓存 |
| 权威服务器 | Authoritative Server | 根据它负责区域的数据给出权威回答 |
| 根服务器 | Root Server | 为根区域提供服务，包括顶级域的委派信息 |

浏览器、操作系统和递归解析服务都可能影响一次实际解析，但不应把它们说成永远固定的调用顺序。下面明确假设没有可用缓存或本地覆盖记录。

## 查询的不只是地址

DNS 中的条目称为资源记录（Resource Record，RR），查询需要说明名字与记录类型。

| 类型 | 含义 | 本课用途 |
| --- | --- | --- |
| A | 地址（Address）记录，保存 32 位 IP 地址 | 最终得到 `192.0.2.20` |
| AAAA | 保存 128 位 IP 地址的地址记录 | 同一名字可以拥有另一类地址 |
| NS | 名称服务器（Name Server）记录 | 描述区域的权威名称服务器 |
| CNAME | 规范名称（Canonical Name）记录 | 把别名指向另一个名字 |

本课假设教学记录为 `www.example.com. A 192.0.2.20`，生存时间（Time to Live，TTL）为 300 秒。这是用于推演的配置，不是声称该真实域名当前一定这样配置。

## 逐步推演

### 第一步：客户端请求递归服务

客户端需要 `www.example.com.` 的 A 记录，将查询交给配置好的递归解析器 R。

| 检查位置 | 本例结果 |
| --- | --- |
| 客户端可用的本地结果 | 未命中 |
| R 的目标记录缓存 | 未命中 |
| R 是否知道根服务器入口 | 是，已有必要的引导信息 |

客户端希望 R 返回结果或错误，而不是让浏览器自己逐个联系所有层级。这里递归描述的是“替调用者完成解析”的责任。

### 第二步：沿根与顶级域的委派前进

R 开始询问有权提供下一步信息的服务器：

| 查询阶段 | 得到的信息 | 下一步 |
| --- | --- | --- |
| 询问根区域 | `com` 的服务器委派信息 | 联系相应顶级域服务器 |
| 询问 `com` 区域 | `example.com` 的服务器委派信息 | 联系该区域的权威服务器 |

这些答复通常是转介，不是 `www.example.com` 的最终地址。为简化过程，本例假设联系下一层需要的服务器地址可以取得，省略辅助查询。

### 第三步：权威服务器返回教学记录

R 向 `example.com` 的权威服务器查询目标记录，得到：

```text
名字：www.example.com.
类型：A
值：192.0.2.20
TTL：300 秒
```

R 按规则缓存记录，并把结果返回客户端。若遇到 CNAME，还需要继续取得其目标名字对应的所需记录；本例没有别名链。

### 第四步：120 秒后的相同查询命中缓存

假设记录刚进入 R 的缓存时剩余有效期为 300 秒，期间没有刷新；120 秒后另一个客户端询问相同名字和类型。

| 项目 | 结果 |
| --- | --- |
| 已经过时间 | 120 秒 |
| 剩余 TTL | `300 - 120 = 180` 秒 |
| 本次是否需要重新走完整委派链 | 不需要，可使用仍有效的缓存 |

在本课普通缓存模型中，过期后需要重新获得可用结果。再次查询也不一定从根开始，因为中间委派等信息可能仍有有效缓存。

## 递归与迭代不要按服务器名字硬分

递归请求要求接收者尽力返回最终结果或错误；迭代查询（Iterative Query）的应答可以指出更合适的服务器，由查询方继续跟进。

常见路径是客户端请求递归解析器，而递归解析器以迭代方式跟进权威层次。两者不是“DNS 有两种互斥模式”，同一次解析中可以同时出现。

上述步骤描述逻辑关系，不承诺每个实际报文都携带同样的完整查询名，也不要求每次都访问根服务器。

## 为什么既有 UDP 又有 TCP

UDP 常用于传统 DNS 查询，减少简单请求中的连接建立步骤。TCP 也是 DNS 正式支持的传输方式，通用实现需要具备相应支持。

例如 UDP 响应被标为截断时，客户端可能转用 TCP 取得完整内容。TCP 并不只用于区域传送；也不能把“短查询通常用 UDP”写成“DNS 必须用 UDP”。

本课没有展开加密 DNS 的额外封装，不能据此把这条经典传输路径当成所有浏览器的唯一实现。

## 常见误解

- **“根服务器保存所有网站的最终地址。”** 它通常先提供合适的委派方向。
- **“修改权威记录后，所有缓存立即更新。”** 仍有效的旧缓存可能继续被使用到相应期限。
- **“域名和 IP 一一对应。”** 一个名字可有多个地址，多个名字也可指向同一地址。
- **“DNS 超时就是名字不存在。”** 超时只说明未及时取得所需响应，与明确的不存在答复不同。

## 选择题

本课中，递归解析器首次询问根服务器后，通常先得到什么？

- A. `www.example.com` 网页的完整内容
- B. 全世界所有域名的地址表
- C. 继续查询 `com` 区域的委派信息
- D. 客户端与网站的 TCP 连接

**答案：C。** 根区域帮助定位下一层权威信息。A 混淆命名与应用内容，B 忽略分布式层次，D 是取得地址后可能进行的另一种协议操作。

## 面试追问

**浏览器取得 IP 地址，就说明能访问网站吗？**

不能。还要看路由、目标端口、传输连接、安全握手和应用处理等环节。DNS 只解决其中的命名查询问题。

**这里的 TTL 与 IP 包中的 TTL 是一回事吗？**

两者英文同名，但作用不同。DNS TTL 主要表达记录缓存期限；IP 首部中的 TTL 用于限制分组在网络中的生存范围，不能用 DNS 的 300 秒直接解释 IP 转发次数。
