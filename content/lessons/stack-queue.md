# 栈与队列

## 面试回答

栈（Stack）遵循后进先出（Last In, First Out，LIFO），通常在同一端入栈和出栈；队列（Queue）遵循先进先出（First In, First Out，FIFO），通常从队尾入队、队头出队。它们首先是抽象数据类型（Abstract Data Type，ADT），描述允许的操作和顺序，不限定必须用数组或链表实现。合适实现可以让主要操作达到 O(1)，但需要区分固定容量、扩容的摊还成本，以及是否错误地用整体搬移实现出队。

## 从零理解

把数据看成依次到来的 A、B、C。如果每次取走最近加入的一个，就是栈；如果每次取走等待最久的一个，就是 FIFO 队列。

ADT 规定“能做哪些操作、操作有什么语义”，不直接规定内存布局。

| 结构 | 加入 | 移除并返回 | 只查看不移除 |
| --- | --- | --- | --- |
| 栈 | `push`，入栈 | `pop`，出栈 | `peek` 或 `top`，查看栈顶 |
| 队列 | `enqueue`，入队 | `dequeue`，出队 | `peek` 或 `front`，查看队头 |

具体 API 名称可以不同，判断结构应看行为规则。例如某个库使用 `append` 与 `popleft` 组合实现 FIFO，并不因为名字不同就不再是队列。

双端队列（Double-Ended Queue，Deque）允许两端插入和删除，可以用来实现栈或队列。优先队列（Priority Queue）按优先级选择元素，不承诺普通 FIFO 顺序。

## 读状态前先约定方向

本课把栈写为 `[栈底 ... 栈顶]`，把队列写为 `[队头 ... 队尾]`，均从左到右列出。

```text
栈：[A, B, C]    下一次 pop 返回 C
队列：[A, B, C]  下一次 dequeue 返回 A
```

图中列表相同，移除规则不同。只看容器中有哪些元素，不能确定下一个会返回谁。

## 逐步推演

### 第一步：让 A、B、C 依次进入

从空栈和空队列开始，依次加入 A、B、C。

| 已完成操作 | 栈，左底右顶 | 队列，左头右尾 |
| --- | --- | --- |
| 加入 A | `[A]` | `[A]` |
| 加入 B | `[A, B]` | `[A, B]` |
| 加入 C | `[A, B, C]` | `[A, B, C]` |

此时栈顶是 C，队头是 A。两者都保存 3 个元素，但下一次移除结果已经不同。

### 第二步：各移除一个元素

栈执行一次 pop，队列执行一次 dequeue。

| 结构 | 返回值 | 操作后状态 |
| --- | --- | --- |
| 栈 | C | `[A, B]` |
| 队列 | A | `[B, C]` |

栈返回最近进入的 C，队列返回最早进入且尚未移除的 A。被移除的元素不再属于容器。

### 第三步：插入新的 D

继续往两个容器中加入 D。

| 结构 | 操作后状态 | 只查看下一项 |
| --- | --- | --- |
| 栈 | `[A, B, D]` | D |
| 队列 | `[B, C, D]` | B |

peek 只观察，不删除。刚到的 D 会成为栈下次移除的对象，但不会越过 FIFO 队列里等待中的 B、C。

### 第四步：把剩余元素全部取出

| 第几次继续移除 | 栈返回 | 队列返回 |
| --- | --- | --- |
| 1 | D | B |
| 2 | B | C |
| 3 | A | D |

连同第二步已经移除的元素，完整输出分别是 `C、D、B、A` 与 `A、B、C、D`。栈的输出并不是把所有输入简单整体倒序，因为输入和输出在过程中交错发生。

最后两者都为空。再次移除应遵守 API 的空容器约定，例如抛出异常或返回专门的空结果，不能假装还有一个普通元素。

## 双容器实验

初始栈与队列都包含依次进入的 A、B、C。实验可以同时加入同一个新元素，再分别从两个容器取出数据。竖直栈的顶部是最近加入项；队列从队头开始显示，必要时换行但逻辑顺序不改变。

两个容器的容量均限制为 6，空时不能移除，任一容器满时不能再同时加入。限制用于清晰展示边界，不代表所有栈或队列天然固定容量。两边可独立移除，因此不能仅凭“加入过相同元素”就假设当前长度与内容仍相同。

## 实现为什么影响复杂度

数组栈通常在末尾 push、pop，不需要搬移前面的元素。如果使用动态数组，扩容可能让单次 push 变为 O(n)，采用合适增长策略时 push 可摊还为 O(1)。

链表栈可以在表头插入和删除。链表队列维护 head 与 tail 后，可以在队尾加入、队头移除；从一个元素变为空时，要同时维护好两个引用。

循环队列（Circular Queue）可复用数组中已经腾出的槽位。假设容量为 4，位置从 0 到 3，下一位置可用 `(位置 + 1) % 4` 计算；从 3 前进会回到 0，而不是无限向后增长。

实现还必须区分“空”和“满”，例如额外保存元素数量，或保留一个不用的槽位。只看到 head 与 tail 相等，不足以推断状态，必须结合具体约定。

如果用普通连续数组的“删除第 0 项并搬移后续元素”实现出队，每次可能花 O(n)。Python 文档明确区分了列表头部删除与 deque 两端操作的成本。[Python collections.deque](https://docs.python.org/3/library/collections.html#collections.deque)

## 规则与应用如何对应

撤销操作通常先撤销最近完成的动作，适合栈的顺序。嵌套括号匹配也需要先匹配最近尚未闭合的左括号。

需要按到达顺序处理的任务可用 FIFO 队列。实际操作系统或服务系统也可能采用优先级、公平性等其他调度策略，不能把所有“排队”都理解成严格 FIFO。

## 常见误区

- **“栈就是递归，队列就是线程池。”** 它们是通用数据结构；这些应用可能使用它们，但不等同于它们。
- **“peek 和 pop 都只是读取。”** pop 会改变容器，peek 不移除元素。
- **“用数组就不能实现队列。”** 循环数组是常见实现，关键是索引和容量管理。
- **“返回 -1 就能通用地表示空。”** 若 -1 本来就是合法数据，会产生歧义；接口应明确区分空状态。

## 选择题

空栈依次执行 `push(A)、push(B)、pop()、push(C)、pop()`。两次 pop 的返回值依次是什么？

- A. A、B
- B. A、C
- C. B、A
- D. B、C

**答案：D。** 加入 A、B 后，第一次 pop 取出栈顶 B，剩下 A；再加入 C，第二次 pop 取出 C，仍剩下 A。选择 A 或 B 都把栈误当成了 FIFO 队列。

## 面试追问

**为什么“栈操作 O(1)”还需要说清实现？**

固定容量数组的末尾操作可以是最坏 O(1)，动态数组入栈可能触发扩容，通常讨论摊还 O(1)。链式实现还涉及分配方式。接口只规定顺序，具体实现和成本模型决定复杂度保证。
