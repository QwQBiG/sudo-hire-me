# 定宽整数加法：进位不等于有符号溢出

## 先确定计算规则

整数的数学和可以任意大；一个固定 `n` 位的结果却只能留下 `n` 个位。本课先采用**固定宽度位模式模型**：两个操作数和结果都有相同位宽，从最低位向最高位逐列相加，结果只保留低 `n` 位。这是理解硬件表示的模型，不预设某种编程语言会怎样处理越界。

以 8 位为例，位模式 `11111111` 可以按无符号整数（Unsigned Integer）解释为 `255`，也可以按补码（Two's Complement）有符号整数解释为 `-1`。两个数的位相加规则相同；“有没有溢出”要先选定解释范围。

| 解释方式 | 8 位可表示范围 | 溢出的判断依据 |
| --- | --- | --- |
| 无符号 | `0..255` | 非负整数的数学和大于 255 |
| 补码有符号 | `-128..127` | 有符号操作数的数学和超出这个范围 |

更一般地，无符号上限是 `2ⁿ-1`；补码范围是 `-2ⁿ⁻¹..2ⁿ⁻¹-1`。**进位（Carry）**只说明一列向更高位传了 `1`；最高位之外的进位，在本模型中恰好对应无符号加法越界，但不能单独判断有符号溢出（Signed Overflow）。

## 逐列算一次：127 加 1

先把十进制数写成 8 位：`127 = 01111111`，`1 = 00000001`。

```text
    01111111  (127)
  + 00000001  (1)
  ----------
    10000000
```

最右边第 0 位是 `1 + 1 = 10₂`，本位写 `0`，向第 1 位进 `1`。第 1 至第 6 位都是 `1 + 0 + 1 = 10₂`，继续传递进位；第 7 位是 `0 + 0 + 1 = 1`，所以最高位之外没有进位。

按无符号解释，数学和 `128` 仍在 `0..255` 内，**不溢出**。按补码解释，两个操作数是 `127` 和 `1`，数学和 `128` 超出 `-128..127`；保留下来的 `10000000` 却被解释为 `-128`，因此**发生有符号溢出**。`-128` 是截断后的位模式解释，不是数学和。

## 再算一次：有进位却没有有符号溢出

```text
    11111111  (无符号 255；补码 -1)
  + 00000001  (1)
  ----------
  1 00000000  (左侧 1 是第 8 位进位)
```

低 8 位为 `00000000`。无符号数学和 `255 + 1 = 256`，超过上限，故无符号溢出；补码数学和 `-1 + 1 = 0`，可表示，故有符号不溢出。两种例子把“进位”和“有符号溢出”彻底分开。

对于**加法且操作数与结果同为 n 位补码**，还可快速判断：两个操作数同号、截断后的结果却变成相反符号，才发生有符号溢出。不同号相加不会超过补码上下限。这个判据不能不加条件地套到减法、乘法或发生整数提升的表达式上。

## 面试回答

在固定 n 位加法中，先求数学和，再只保留低 n 位。无符号溢出是数学和超过 `2ⁿ-1`，等价于最高位向外产生进位；补码有符号溢出是有符号数学和超出 `-2ⁿ⁻¹..2ⁿ⁻¹-1`，可用“同号相加却得到异号结果”判断。`127 + 1` 的 8 位结果没有向外进位却发生有符号溢出；`255 + 1` 向外进位，但若把 `255` 的位模式解释为 `-1`，有符号和 `0` 不溢出。语言层面的结果还要按具体类型与规范判断。

## 实验：让进位从低位走到高位

实验接受 **4 或 8 位**的两个无符号输入 `0..2ⁿ-1`；这些输入首先是位模式。点击“推进一位”从最低位检查本位两个输入和传入进位；顶部同时给出无符号与补码解释，最终分别判定两种溢出。把输入设为 8 位 `127 + 1`，再试 `255 + 1`，观察两个结果标签为何互换。

实验中的“溢出”是数学和相对**选定定宽表示范围**越界，不意味着运行中的 JavaScript `Number` 自身发生溢出。JavaScript 普通数字并不是 4 位或 8 位整数。

## 语言规则不能照搬位模式图

Java 的 `int` 加法溢出时按规范保留数学和的低 32 位；但 Java 的 `byte + byte` 会先进行二元数值提升，以 `int` 计算，不能把它直接说成“8 位加法自动回绕”。C++ 的无符号整数运算按模 `2ⁿ` 处理，而**普通有符号整数算术溢出是未定义行为**，不能保证它得到本课图中的回绕值。本课所说的“无符号溢出”是数学和超出 n 位表示范围；C++ 标准对已定义的无符号取模运算不使用未定义溢出的含义。[Java 语言规范：数值提升与加法](https://docs.oracle.com/javase/specs/jls/se21/html/jls-5.html#jls-5.6)、[C++ 标准草案：基本整数类型](https://eel.is/c++draft/basic.fundamental)

## 常见错误

- **“出现最高位进位就一定是有符号溢出。”** `11111111 + 1` 有进位，但按补码是 `-1 + 1 = 0`。
- **“最高位从 0 变 1 就是所有意义上的溢出。”** `127 + 1` 对无符号 8 位数仍可表示。
- **“低位结果是 -128，所以 127 + 1 等于 -128。”** 数学和是 128；`-128` 是把保留的 `10000000` 按 8 位补码解释。
- **“小类型表达式都按小类型位宽计算。”** 例如 Java `byte` 运算可能先提升为 `int`。

## 选择题

固定 8 位加法 `11111111 + 00000001` 只保留低 8 位。以下判断哪项正确？

- A. 无符号溢出，有符号补码不溢出
- B. 无符号不溢出，有符号补码溢出
- C. 两种解释都溢出
- D. 两种解释都不溢出

**答案：A。** 无符号数学和为 256，超出 255；补码数学和为 `-1 + 1 = 0`，可表示。B 把两种结果颠倒，C 把进位当作有符号溢出，D 忽略了无符号上限。

## 面试追问

**两个负数相加怎样判断？** 先按补码解释操作数。例如 8 位 `10000000 + 11111111` 是 `-128 + (-1) = -129`，超出下限；低 8 位为 `01111111`，显示成正数 127。这满足“两个负数却得到正结果”的判据。
