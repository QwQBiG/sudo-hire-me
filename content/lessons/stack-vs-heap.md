# 栈和堆：真正要问的是谁活到什么时候

## 先区分抽象规则与典型实现

调用栈（Call Stack）常用来管理函数调用帧：一次调用的参数、返回位置和某些局部状态随调用进入、退出。堆（Heap）通常指运行时管理的动态分配区域。它们是理解典型实现的好模型，但 **C 标准规定的是对象的存储期（Storage Duration）与生命周期，不强制所有自动变量都物理地放在硬件栈上**；优化器可能把值放寄存器，某些运行时也会采用不同布局。[ISO C N1570：存储期](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)

这节课只看单线程 C 示例，假设 `malloc` 成功。自动存储期的局部对象在其块的执行结束后不再有效；`malloc` 得到的动态对象在 `free` 前保持分配状态。**指针变量的位置**与**它指向对象的位置和寿命**是两个问题。

## 逐步推演

### 第一步：同时得到局部对象与动态对象

```c
#include <stdlib.h>

void work(void) {
  int local = 7;
  int *p = malloc(sizeof *p);
  if (p == NULL) return;
  *p = 9;
  /* 此处 local 和 *p 均可在各自规则下访问。 */
  free(p);
}
```

`local` 是一个局部整数对象，`p` 也是局部**指针变量**；`malloc` 返回的地址指向另一块动态分配对象。`*p = 9` 写的是目标整数，不是把局部指针变量 `p` 改成 9。典型图如下，图只说明关系，不宣称具体物理地址：

```text
调用中的局部状态：local = 7，p ──→ 动态分配整数 = 9
```

### 第二步：释放目标与结束调用不是同一事件

`free(p)` 结束该动态分配对象的可用生命周期；随后继续使用 `*p` 是错误的，不能预测一个固定数值。`free` 也不会自动把指针变量 `p` 设置为 `NULL`。当 `work` 返回时，局部的 `local` 和 `p` 也结束其自动存储期。[ISO C N1570：`malloc` 与 `free`](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)

若提前返回却忘记 `free`，动态对象仍占据分配资源但再也找不到可释放它的地址，就发生内存泄漏（Memory Leak）。因此需要把每条成功分配路径与相应清理路径配对；即使写了 `free`，也还要避免其他指针继续指向已释放对象。

### 第三步：拒绝返回局部对象地址

下列代码是**错误示例，不要调用后解引用返回值**：

```c
int *bad(void) {
  int x = 7;
  return &x;
}
```

`x` 在 `bad` 返回时已不再有效；拿到的指针不能安全地代表一个仍存在的 `int` 对象。不能说“它必然打印 7”或“它必然立刻崩溃”：错误程序的后续行为没有这类固定保证。若只要数值，应直接 `return x;`；若要让对象跨过函数返回继续存在，需要合适的所有权和生命周期设计。

### 第四步：换语言时重新确认规则

Java 虚拟机（Java Virtual Machine，JVM）规范区分每线程的虚拟机栈帧与共享堆，并描述类实例和数组从 JVM 堆分配；但也允许帧在堆上分配，具体布局和优化留给实现。不能据此简单断言“Java 的所有局部变量都一定在物理栈内”或“所有 `new` 对象都会留下可观察的独立堆块”。[JVM 规范：运行时数据区](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-2.html#jvms-2.5)

Rust 以所有权和借用规则约束何时可以使用值；`Box<T>` 提供堆分配的拥有者，但某个 `T` 是否在栈上不能仅凭“它是局部变量”推断所有细节。[Rust 官方教材：`Box<T>`](https://doc.rust-lang.org/book/ch15-01-box.html)

## 面试回答

栈通常管理调用帧，动态堆分配对象的寿命通常独立于单次函数调用。回答时先区分对象与指向对象的局部指针：C 中 `p` 可是自动局部变量，而 `malloc` 的目标由 `free` 结束分配；返回局部 `x` 的地址会得到不能在返回后安全使用的指针，忘记释放动态对象则可能泄漏。语言标准与虚拟机规定的是生命周期和可观察行为，不能把常见栈/堆布局绝对化为每种语言的物理实现。

## 常见错误

- **“指针 `p` 指向堆，所以 `p` 自己也一定在堆。”** 指针变量和目标对象可有不同存储期。
- **“函数返回时堆对象自动消失。”** C 的动态分配需要按接口释放；忘记释放可能泄漏。
- **“`free(p)` 后 `p` 自动变成空指针。”** `free` 不改写这个局部变量的值。
- **“拿到局部地址后马上访问通常能读到旧值，所以没问题。”** 不能以偶然结果证明生命周期合法。

## 选择题

在本课 C 示例中，`p` 是 `work` 的局部指针变量，`malloc` 成功返回动态分配对象地址。哪项最准确？

- A. `p` 与 `*p` 必定是同一个对象
- B. `free(p)` 后可继续可靠读取 `*p`
- C. `p` 的局部生命周期与动态目标的分配生命周期是两个问题
- D. `work` 返回会自动对所有 `malloc` 对象调用 `free`

**答案：C。** `p` 保存地址，`*p` 是目标，二者不是同一对象；目标需按动态分配规则处理。A 混淆指针和目标，B 是释放后使用，D 混淆自动与动态存储期。
