# 时间与空间复杂度

## 面试回答

时间复杂度（Time Complexity）描述基本操作数量随输入规模增长的趋势；空间复杂度（Space Complexity）描述所需存储随规模增长的趋势。大 O 记号（Big O Notation）表示渐近上界，Θ 表示渐近紧确界。分析时先定义 n、计算模型和操作，再确定讨论最坏、平均还是摊还情况。忽略常数和低阶项是为了比较增长趋势，不等于它们不影响真实运行时间。额外空间还要包含递归调用栈等开销，并说明是否计入输入和输出。

## 从零理解

假设程序要处理 n 个学生成绩，n 就是输入规模（Input Size）。计算“每位学生加一次分”大约需要 n 次操作，检查所有两两组合则可能需要与 n² 同阶的操作。

复杂度不是用秒作单位。同样的算法在不同机器上会有不同耗时；复杂度主要帮助判断数据量增长以后，成本会怎样增长。

在常见的随机访问机器（Random Access Machine，RAM）计算模型中，固定宽度数值的一次访问、比较和加法通常按常数成本分析。这里的 RAM 是算法计算模型，不是在单独讨论内存条。

如果操作处理任意长整数或长字符串，就不能总把一次加法、一次比较视为 O(1)。先选清楚基本操作，结论才有适用范围。[Open Data Structures：计算模型与渐近记号](https://opendatastructures.org/newhtml/ods/latex/intro.html)

## 常见增长阶怎样读

| 增长阶 | 典型情形 | n 翻倍后的主要增长 |
| --- | --- | --- |
| O(1) | 固定宽度数组的一次下标访问 | 有界，不随 n 增长 |
| O(log n) | 每次把候选区间缩小一半 | 只增加常数量级的步骤 |
| O(n) | 扫描所有元素 | 约 2 倍 |
| O(n log n) | 典型高效比较排序 | 略多于 2 倍 |
| O(n²) | 枚举元素对 | 约 4 倍 |

表中的倍数用于理解对应主导项的趋势，不是用大 O 上界承诺某段程序的精确运行时间。

对数的底数只造成常数倍差异，所以渐近分析常写 `log n`。二分查找的具体次数则通常用 `log₂ n` 来解释。

## 逐步推演

### 第一步：固定要数的操作

下面把所有满足 `0 ≤ j < i < n` 的下标对各计数一次。暂不保存这些对，只增加计数器。

```javascript
function countPairs(n) {
  let count = 0;
  for (let i = 0; i < n; i += 1) {
    for (let j = 0; j < i; j += 1) {
      count += 1;
    }
  }
  return count;
}
console.log(countPairs(4));
console.log(countPairs(8));
```

本例 n 是非负整数。把 `count += 1` 作为要精确计数的操作，输出依次为 `6`、`28`。这不代表循环条件等其他语句完全没有成本。

### 第二步：逐轮列出 n = 4 的状态

| i | j 的取值 | 本轮新增次数 | 累计 count |
| --- | --- | --- | --- |
| 0 | 没有合法 j | 0 | 0 |
| 1 | 0 | 1 | 1 |
| 2 | 0、1 | 2 | 3 |
| 3 | 0、1、2 | 3 | 6 |

这里不是“有两个循环，所以恰好执行 4 × 4 次”。内层上界随着 i 改变，需要先求每轮次数，再相加。

### 第三步：从具体数字推到一般规模

计数语句的次数是等差数列之和：

`T(n) = 0 + 1 + 2 + ... + (n - 1) = n(n - 1) / 2`

展开得到 `n² / 2 - n / 2`。随着 n 增大，二次项主导增长，因此该循环结构的时间复杂度是 Θ(n²)，也可以说属于 O(n²)。

外层推进和条件检查只增加低阶项或同阶的常数倍开销，不改变这个结论。n 为 0 或 1 时循环体计数为 0，公式也成立。

### 第四步：核对增长与空间

| n | 精确计数 n(n - 1) / 2 | 与上一个规模比较 |
| --- | --- | --- |
| 4 | 6 | 起点 |
| 8 | 28 | 约 4.67 倍 |
| 16 | 120 | 约 4.29 倍 |

小规模时并不恰好翻 4 倍；随着 n 增大，二次主导项的比例越来越接近 4。

程序只使用 `n、i、j、count` 等固定数量的数值变量，按固定宽度数值模型分析，辅助空间（Auxiliary Space）为 O(1)。如果把所有下标对存入数组，输出存储就会增长为 Θ(n²)。

## 大 O 不等于最坏情况

大 O 是一种数学界限，最坏情况（Worst Case）则是在同一规模的不同输入中挑成本最大的情况。这是两个不同维度。

例如顺序查找：目标就在第一项时，最好情况是 Θ(1)；目标不存在时，要看完 n 项，最坏情况是 Θ(n)。两种情况都可以各自写上界。

平均情况（Average Case）需要说明输入的概率假设；摊还分析（Amortized Analysis）考察一系列操作的总成本如何分摊，不是先假设“坏情况很少发生”。

Θ(n²) 同时提供匹配的渐近上下界。O(n³) 也是二次函数的合法但较松上界；面试通常期待你给出有意义的紧界，而不是任意很大的上界。

## 常见误区

- **“两个循环一定是 O(n²)。”** 先看循环是否嵌套，以及各轮执行次数；顺序执行两个线性循环仍是 O(n)。
- **“O(1) 就是只执行一步。”** 固定做 100 次也可能是 O(1)，关键是是否随输入规模增长。
- **“没有创建数组，所以额外空间一定是 O(1)。”** 递归调用栈和其他动态状态也要计入。
- **“复杂度更低，小输入就一定更快。”** 常数、缓存、分配和运行环境都会影响实际耗时。

## 选择题

程序先完整扫描 n 个元素，再独立扫描同一批元素一次；每次处理一个元素的成本是 O(1)。总时间的紧确增长阶是什么？

- A. Θ(1)
- B. Θ(log n)
- C. Θ(n)
- D. Θ(n²)

**答案：C。** 两段顺序执行的扫描次数相加，为 `n + n = 2n`，不是相乘。Θ 记号忽略固定倍数 2，得到 Θ(n)。D 把先后执行误当成嵌套执行。

## 面试追问

**如何比较一个 O(n) 算法和一个 O(n log n) 算法？**

先确认二者解决同一个问题、采用相同规模定义，并核对空间和输入前提。渐近增长通常有利于线性算法，但实际选择仍要看规模范围、常数和测量结果。若问题很小，不能只凭复杂度符号断言运行时间。
