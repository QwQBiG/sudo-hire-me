# 缓存一致性：核心 B 的旧副本怎么办

## 问题来自多个私有副本

设两个 CPU 核心都缓存了同一地址所在的缓存行，最初值为 0。核心 A 要写成 1，若核心 B 仍无限期把自己的旧副本当有效值，就无法正确协作。缓存一致性（Cache Coherence）机制协调**同一缓存行**的副本：常见失效式协议让写入方先取得相应写权限，其他副本标为无效；之后其他核心再请求读，须取得有效数据。[Intel 64/IA-32 软件开发手册：MESI Cache Control Protocol](https://cdrdv2-public.intel.com/868137/325462-089-sdm-vol-1-2abcd-3abcd-4.pdf)

一个入门标签是 MESI：已修改（Modified，M）、独占（Exclusive，E）、共享（Shared，S）、无效（Invalid，I）。这里只推演“共享→一方写→另一方再读”，不假装所有 CPU 都使用完全相同的协议消息或层级。[Intel 软件开发手册：MESI 四状态](https://cdrdv2-public.intel.com/868137/325462-089-sdm-vol-1-2abcd-3abcd-4.pdf)

## 两核请求的示意顺序

| 已完成的动作 | A 的副本 | B 的副本 | 说明 |
| --- | --- | --- | --- |
| 双方先读值 0 | S，值 0 | S，值 0 | 两份只读共享副本 |
| A 获得写权限并写 1 | M，值 1 | I，不可再当作有效值 | B 的旧副本被失效 |
| B 随后请求读 | 有效副本按协议提供/协调 | 重新取得值 1 | 不使用被标无效的旧 0 |

第二步时主存未必立刻是 1；修改后的最新值可暂在拥有权限的缓存中。第三步如何响应读请求由具体一致性实现负责，概念上不能直接信任 B 已失效的旧副本。此表是假设这些硬件操作按给定顺序**已经完成**的教学演算，不是无同步多线程程序的保证输出。

## 逐步推演

### 先共享读

A、B 都取得值 0 的同一行，标为共享；此时没有一方独占写权限。

### A 请求修改

A 的写请求使其他副本失效，B 的行进入 I。A 持有新值 1；B 不能再靠本地旧行命中返回 0。

### B 再发读请求

B 发现本地行无效，必须从一致性系统取得有效数据，按本例已完成的硬件顺序读到 1。

### 检查程序层约束

若 C/C++ 两线程无同步地读写同一个普通变量，仍可能构成数据竞争与未定义行为。硬件维护缓存副本，不会自动为语言层程序建立所需的同步或所有跨地址顺序保证。[C++ working draft：数据竞争](https://eel.is/c++draft/intro.races)

## 面试回答

多核可能各持有同一缓存行的副本。失效式缓存一致性协议在一方写时使其他旧副本无效，并在后续读请求时提供有效数据；MESI 用 M/E/S/I 等状态描述常见权限与副本状态。但缓存一致性只解决硬件副本协调的一部分问题，和程序的内存顺序、原子操作、锁是不同层次，不能据此认为无同步共享变量访问必然正确。

## 选择题

按本课已完成动作的教学模型，A 写 1 后 B 的旧行已处于 I，B 下一次读应怎样处理？

- A. 直接用本地旧 0，当成命中
- B. 从一致性系统重新取得有效值
- C. B 可以绕过所有一致性规则自行写回旧 0
- D. 这已证明无锁 C++ 读写同一普通变量安全

**答案：B。** I 表示旧副本不能作为有效命中。A、C 违反失效语义，D 把硬件一致性误当语言同步保证。
