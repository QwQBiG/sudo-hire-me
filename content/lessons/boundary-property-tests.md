# 为什么“正常输入通过”还不够

## 先写契约，测试才有目标

假设函数 `clamp(x, 0, 10)` 的约定是：当 `x < 0` 返回 0，`0 ≤ x ≤ 10` 返回 x，当 `x > 10` 返回 10；输入限定为普通有限数值。只测 `x = 5`，即使错误实现把所有大于等于 10 的值都返回 9，这个测试仍会通过。边界用例要从条件分支和取值范围**推出来**，而不是靠随意多试几个数字。

边界值分析（Boundary Value Analysis）常检查边界本身、边界前后和特殊输入；性质测试（Property-Based Testing）检查一批输入共同应满足的不变量，而不仅给每个输入写一个固定答案。两者互补：性质测试能探索更多组合，但性质本身也可能写错，生成器也未必覆盖到最关键边界。

## 逐步推演

### 第一步：画出三个输出区域

本例有 `x < 0`、`0 ≤ x ≤ 10`、`x > 10` 三个区域。选 `-1, 0, 5, 10, 11`，分别覆盖下界外、下界、内部、上界、上界外。若输入只允许整数，这组点足够示范边界思路；若允许小数，还可检查 `-0.1` 与 `10.1`。不要在没有输入约定时自动把 NaN、无穷大或字符串混进同一契约。

| 输入 x | 预期 | 主要检查 |
| ---: | ---: | --- |
| -1 | 0 | 下界外 |
| 0 | 0 | 恰好下界 |
| 5 | 5 | 区间内部 |
| 10 | 10 | 恰好上界 |
| 11 | 10 | 上界外 |

### 第二步：故意放一个看似合理的错误

错误实现把 `x >= 10` 都返回 9。它在 `x=5` 时看似正确，却在 `x=10` 与 `x=11` 暴露。测试 `x=10` 很重要，因为它还区分 `<` 与 `<=` 的边界写法。若只测 11，能发现结果错误，却不一定明确是边界归属还是上界值写错。

能杀死一个错误实现的用例比十个重复同一正常路径的用例更有信息量。真实测试还需考虑其它潜在错误，例如把下界外也返回 10；因此不能只针对已经见到的一个 bug 设计全部测试。

### 第三步：从契约写出通用性质

对约定输入，可断言 `0 ≤ clamp(x,0,10) ≤ 10`；若 `0 ≤ x ≤ 10`，输出应等于 x；重复裁剪不改变结果，即 `clamp(clamp(x,0,10),0,10) = clamp(x,0,10)`。可以生成许多有限数值检查这些性质。第一条“结果在范围内”抓不到把 11 错误返回 9，因为 9 仍在范围内；把多种独立性质组合，才更容易定位问题。

性质不是数学证明：随机生成 1000 个输入全部通过，也不能推出所有输入都正确。对有明确阈值的函数，应把 0 和 10 等固定边界放进种子用例，不依赖随机碰到。

### 第四步：让失败能被复现

性质测试失败时，记录生成种子、输入和实际输出；若工具会缩小反例（Shrinking），保留缩小后的最小失败输入。这样别人能复现“哪种输入打破哪条性质”。如果只报告“随机测试偶尔失败”，却没有输入和种子，后续定位会很难。

## 面试回答

我先根据函数契约列出分支与输入域，再选边界本身和两侧用例，例如 `-1、0、5、10、11`。除了固定预期值，还会写输出范围、区间内保持原值和幂等性等性质，检查更多输入。测试通过只能说明已覆盖输入与性质没有发现错误，不是对所有输入的形式证明；失败时应保留可复现的输入和种子。

## 为什么不要只追测试数量

两百个都落在 `1..9` 的用例，仍可能完全错过 `x=10` 的分支错误。覆盖率能提示哪些代码没有走到，但“走到一行”不等于检查了正确输出。设计测试要问：这个输入能区分哪两个可能的实现？断言是否对应真实契约？

## 常见误区

- **只测区间中间值。** 可能漏掉边界的 `<` 与 `<=` 错误。
- **只检查输出在合法范围内。** 错误的 9 也可能在 0 到 10 内。
- **认为随机输入多就等于证明。** 有限采样不能覆盖无限或巨大输入域。
- **失败不留输入。** 无法重复出现的失败难以定位和回归。

## 选择题

错误实现把所有 `x >= 10` 返回 9。以下哪组用例最直接暴露上界错误？

- A. `x = 3` 与 `x = 5`。
- B. `x = 10` 与 `x = 11`。
- C. 反复测 `x = 5` 一百次。
- D. 只检查输出是否介于 0 和 10。

**答案：B。** 正确结果在 10 与 11 都应为 10，错误实现返回 9；A、C 未触及边界，D 的范围性质单独不能发现这个错误。

## 面试追问

若输入域还允许 NaN 或不同类型，要先与需求方确定处理契约：返回错误、拒绝输入，还是按语言的数值规则传播。没有契约，就不能把某个语言的偶然行为写成通用正确答案。
