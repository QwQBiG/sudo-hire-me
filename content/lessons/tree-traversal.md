# 二叉树与三种遍历

## 面试回答

二叉树（Binary Tree）的每个节点最多有两个孩子，分别称为左孩子与右孩子，左右位置有区别。前序遍历（Preorder Traversal）按根、左子树、右子树处理；中序遍历（Inorder Traversal）按左子树、根、右子树处理；后序遍历（Postorder Traversal）按左子树、右子树、根处理。这里的规则递归应用于每棵子树，差别是访问当前节点的时机。若每次访问成本为 O(1)，三种遍历时间均为 Θ(n)，普通递归需要 O(h) 调用栈，h 为树高，退化链状树中可能达到 O(n)。

## 从零理解

树（Tree）是一种层次关系。根节点（Root Node）位于最上层，没有父节点；非根节点有一个父节点（Parent Node），可以有自己的孩子节点（Child Node）。没有孩子的节点叫叶节点（Leaf Node）。

本课使用这棵固定二叉树，字母只是节点标签，不是排序规则：

```text
        A
       / \
      B   C
     / \   \
    D   E   F
```

| 节点 | 左孩子 | 右孩子 | 所在关系 |
| --- | --- | --- | --- |
| A | B | C | 整棵树的根 |
| B | D | E | A 的左子树的根 |
| C | 空 | F | A 的右子树的根 |
| D、E、F | 空 | 空 | 叶节点 |

以 B 为根的子树（Subtree）包含 B、D、E，不只包含紧挨着 B 的一层。所谓“先遍历左子树”，是把整棵左子树按同样规则处理完，才继续其他部分。

只有右孩子的 C 与只有左孩子的节点结构不同。不能把“每个节点最多两个孩子”误解成左右位置可以忽略。

## 访问和经过不是一回事

遍历（Traversal）按约定顺序处理所有节点。本课的“访问”特指把当前节点标签写入输出序列，不是“控制流第一次到达节点”。

中序递归首先进入 A 对应的函数，却还不能输出 A，因为必须先处理 A 的整棵左子树。因此中序序列的第一个标签是 D，而不是 A。

每种遍历都会访问每个实际节点一次，但递归过程中还包含调用、返回与检查空孩子。这些动作不必各输出一个标签。[OpenDSA：二叉树遍历](https://opendsa-server.cs.vt.edu/ODSA/Books/CS2/html/BinaryTreeTraversal.html)

## 前序：当前根先被访问

规则是 `根 → 左子树 → 右子树`。

1. 当前根为 A，先输出 A。
2. 处理左子树 B：先输出 B，再处理 D，最后处理 E，得到 B、D、E。
3. 处理右子树 C：先输出 C，左孩子为空，随后处理 F，得到 C、F。

合并后是 `A、B、D、E、C、F`。

前序的“根先”指每棵子树的根都先于自己的后代被访问，不是仅仅把整棵树的 A 提前一次。

## 中序：左子树完成后访问根

规则是 `左子树 → 根 → 右子树`。

| 当前子树 | 左子树的输出 | 当前根 | 右子树的输出 | 完整输出 |
| --- | --- | --- | --- | --- |
| 以 B 为根 | D | B | E | D、B、E |
| 以 C 为根 | 空 | C | F | C、F |
| 以 A 为根 | D、B、E | A | C、F | D、B、E、A、C、F |

注意 A 的左子树中 E 也必须完成，才能轮到 A。不要访问 B 后就直接回 A 而漏掉 E。

## 后序：子树完成后访问根

规则是 `左子树 → 右子树 → 根`。

B 的左子树先输出 D，右子树再输出 E，然后才输出 B，得到 `D、E、B`。C 的左子树为空，右子树输出 F，然后输出 C，得到 `F、C`。

最后 A 在两边全部完成后被访问，完整结果是 `D、E、B、F、C、A`。

当父节点的结果依赖子节点的结果时，这种顺序很自然。例如表达式树中的运算符需要先拿到左右操作数，再计算自己的值。

## 一个函数里的三个访问位置

下面代码只改变输出语句相对于递归调用的位置。输入须是有限且无环的二叉树；缺失孩子用 `null` 或 `undefined` 表示。

```javascript
function traverse(node, order, output = []) {
  if (node == null) return output;
  if (order === "pre") output.push(node.value);
  traverse(node.left, order, output);
  if (order === "in") output.push(node.value);
  traverse(node.right, order, output);
  if (order === "post") output.push(node.value);
  return output;
}
const root = {
  value: "A",
  left: { value: "B", left: { value: "D" }, right: { value: "E" } },
  right: { value: "C", right: { value: "F" } }
};
console.log(traverse(root, "pre").join(" "));
console.log(traverse(root, "in").join(" "));
console.log(traverse(root, "post").join(" "));
```

三行输出依次为 `A B D E C F`、`D B E A C F`、`D E B F C A`。本例调用者保证 order 为 `pre`、`in` 或 `post`；传入其他值不会输出节点，因此实际接口应在边界校验模式。

网站实验采用同一棵树，可逐个观察输出，也可在预测模式中判断下一个访问位置。错误预测不改变已访问序列，避免把尝试次数误当成算法访问次数。

## 时间和空间分别怎么算

设实际节点数量为 n，高度 h 按最长根到叶路径的节点数计算；本例 n = 6、h = 3。也有教材按边数定义高度，此时本例为 2，差一常数不改变渐近结论。

每个节点各访问一次，每个孩子链接也只处理常数次。在单次访问为常数成本的模型中，总时间是 Θ(n)，不是“每层乘每层”而得到 Θ(n²)。

同时活跃的递归调用沿一条从根到当前节点的路径展开，额外调用栈为 O(h)。平衡形态时 h 为 Θ(log n)，如果每个节点只有一个孩子，h 可达到 n。因此不能无条件回答“遍历空间 O(log n)”。[Open Data Structures：递归深度与树高](https://opendatastructures.org/newhtml/ods/latex/binarytrees.html)

本例代码额外把所有标签保存到 output 数组，输出存储为 Θ(n)。说 O(h) 时仅指调用栈；如果把输出也计入总辅助空间，必须把它另外计入。

## 中序为什么不一定有序

普通二叉树只规定结构，不要求键的大小关系。本例中序是 `D、B、E、A、C、F`，显然不是字母升序。

二叉搜索树（Binary Search Tree，BST）额外维护搜索次序：在不允许重复键的常见定义下，每个节点左子树的键都小于自身，右子树的键都大于自身。在这一不变量下，中序遍历才得到升序键序列；允许重复键时还须说明重复值的存储约定。

“二叉树”与“二叉搜索树”不能省略限定词混用，也不能由中序遍历算法本身推出输入树一定满足搜索性质。

## 常见误区

- **“前中后指先访问左、中、右三层。”** 指的是当前根在两棵子树之间的访问时机，不是树的层次。
- **“进入递归函数就必须输出当前节点。”** 中序与后序需要先完成规定的子树；进入和访问是不同动作。
- **“中序遍历任何二叉树都会升序。”** 需要二叉搜索树的排序不变量。
- **“叶节点不递归，所以不算一次调用。”** 叶节点仍有自己的调用和访问，只是孩子为空。
- **“每个节点最多两个孩子，所以树高总是 log n。”** 单孩子链同样是合法二叉树，可能有线性高度。

## 选择题

保持本课的树结构不变，中序遍历访问完 E 后，下一个访问的节点是什么？

- A. B
- B. A
- C. C
- D. F

**答案：B。** 以 B 为根的左子树已按 D、B、E 全部完成，控制流返回 A，此时访问 A，再进入右子树。A 选项重复访问已经输出过的 B；C 和 D 都跳过了必须在右子树之前访问的根 A。

## 面试追问

**递归能改成迭代吗？是不是就不需要额外空间？**

可以用显式栈（Explicit Stack）记录尚未完成的节点与访问阶段。例如中序先沿左链接把节点压栈，左侧为空后弹出一个节点并访问，再转向它的右子树。保存的路径仍可能长达 h，因此这种写法通常仍需要 O(h) 额外空间，只是状态从运行时调用栈移到程序维护的容器。

也存在利用父链接或临时修改链接的其他遍历方法，但它们有额外前提与维护成本，不能用来省略普通栈实现的空间分析。
