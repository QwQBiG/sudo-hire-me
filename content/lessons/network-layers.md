# 网络分层与一次转发

## 面试回答

网络分层把通信任务拆成不同职责：应用层规定消息含义，传输层提供进程间通信能力，网络层负责跨网络寻址与转发，数据链路层负责一段链路上的帧传输，物理层负责信号传送。发送时上层数据由下层逐步封装，接收时按协议解释并交给相应上层。普通路由器转发主要依据网络层信息，跨越不同链路时会重新封装链路层帧。分层模型是组织职责的方式，不表示每层都对应一个独立设备。

## 从零理解协议与封装

协议（Protocol）是通信双方共同遵守的消息格式、含义和处理规则。只知道“发来了一串字节”不够，还需要知道它表示什么、怎样判断是否完整。

封装（Encapsulation）是把上层数据作为本层负载，并按本层协议添加控制信息。例如传输层添加端口信息，网络层添加源和目的地址，链路层再组成可以在当前链路发送的帧。

| 五层教学模型 | 主要问题 | 常见数据单位 |
| --- | --- | --- |
| 应用层 | 这条消息表达什么业务含义 | 应用消息 |
| 传输层 | 主机中的哪个通信端点参与传输 | 报文段或数据报 |
| 网络层 | 怎样跨网络送往目的地址 | 分组、网络层数据报 |
| 数据链路层 | 怎样通过当前链路到达相邻节点 | 帧（Frame） |
| 物理层 | 怎样用信号表达和传送比特 | 比特流 |

网际协议（Internet Protocol，IP）属于网络层。常见互联网四层模型将这里的链路和物理职责归入链路层；开放系统互连（Open Systems Interconnection，OSI）是另一套七层参考模型。层数不同不代表同一数据包突然换了协议。

## 地址和端口不是同一类编号

IP 地址是网络层地址，端口（Port）用于区分传输层通信端点。链路上的媒体访问控制（Media Access Control，MAC）地址，则用于以太网等技术的本地帧传送。

本课使用网际协议第 4 版（Internet Protocol Version 4，IPv4）和传输控制协议（Transmission Control Protocol，TCP）。假设 TCP 连接已经建立，应用要发送约定好的计算请求 `ADD 2 3`。

```text
客户端 A：192.0.2.10，端口 50000
路由器入口：192.0.2.1
路由器出口：198.51.100.1
服务器 S：198.51.100.20，端口 8080
路径：A -> 路由器 -> S
```

两个链路分别使用 `/24` 网络前缀，即前 24 位标识本例中的网络部分。为聚焦转发，假设链路信息已经准备好，没有地址转换、隧道或分片。

## 逐步推演

### 第一步：从应用消息到传输层端点

客户端计算程序交出 `ADD 2 3` 的字节。应用协议负责约定它表示求和；TCP 不理解加法含义。

| 字段 | 本次发送 |
| --- | --- |
| 源端口 | 50000 |
| 目的端口 | 8080 |
| 应用数据 | `ADD 2 3` |

传输层还会添加本协议需要的其他字段。一次应用写入和一个传输层报文段不必一一对应，这里仅跟踪承载该数据的一次示意封装。

### 第二步：发往服务器的包先交给网关

A 根据本地网络前缀判断服务器不在同一网络，将数据包交给下一跳路由器。

| 层次 | 源 | 目的 |
| --- | --- | --- |
| IPv4 数据包 | `192.0.2.10` | `198.51.100.20` |
| 第一段以太网帧 | `MAC-A` | `MAC-R入口` |

表中的 MAC 名称是便于跟踪的符号。IP 目的仍是服务器，帧目的则是本链路下一跳。IPv4 主机可通过地址解析协议（Address Resolution Protocol，ARP）取得下一跳对应的 MAC 地址，已有缓存时不必重新查询。

### 第三步：路由器更换链路封装

路由器收到帧后检查其中的 IPv4 数据包，根据目的地址查询转发表，选择通往服务器网络的出口。

| 字段 | 入口收到 | 出口发出 |
| --- | --- | --- |
| 源 IP | `192.0.2.10` | `192.0.2.10` |
| 目的 IP | `198.51.100.20` | `198.51.100.20` |
| 生存时间（Time to Live，TTL） | 64 | 63 |
| 帧的源与目的 | `MAC-A -> MAC-R入口` | `MAC-R出口 -> MAC-S` |

这里采用通常每经过该路由器减少 1 的情况。IPv4 首部校验信息也需相应更新。路由器没有把原来的整张以太网帧原封不动搬到另一链路，而是为新链路重新封装。

### 第四步：服务器逐层交付

S 从本地帧中取得目的 IP 为自己的数据包，再按其中标明的上层协议交给 TCP，TCP 根据连接信息把字节交给对应应用。

```text
以太网帧 -> IPv4 数据包 -> TCP 连接中的字节 -> 应用协议解析
应用解释 ADD 2 3 -> 算出结果 5
```

端口参与找到通信端点，完整连接还涉及双方地址和端口等信息。TCP 端口 8080 本身不会自动把数据解释成网页或加法请求，具体含义由监听它的应用决定。

## 发送时延和传播时延怎样区分

发送时延（Transmission Delay）是把整段比特送上链路所需的时间；传播时延（Propagation Delay）是信号在介质中经过距离所需的时间。

假设一帧共 1000 字节，链路速率为每秒 1000 万比特，则发送时延为：

`1000 × 8 ÷ 10000000 = 0.0008 秒 = 0.8 毫秒`

若链路长 200 千米，信号速度按每秒 2 亿米计算，传播时延为：

`200000 ÷ 200000000 = 0.001 秒 = 1 毫秒`

不计处理和排队等其他时间，最后一个比特约在开始发送后 1.8 毫秒到达对端。提高发送速率能缩短前者，但不能让既定介质中的传播距离消失。

## 常见误解

- **“经过路由器，IP 目的就改成路由器。”** 普通转发中保留最终目的，链路帧才指向下一跳；地址转换是另一种机制。
- **“一个端口只能对应一个连接。”** 一个监听端口可以服务多个具有不同连接标识的连接。
- **“所有链路都使用相同的 MAC 帧格式。”** 链路技术不同，封装方式也可能不同。
- **“网速就是信号传播速度。”** 链路比特率、传播速度、排队及应用处理是不同因素。

## 选择题

在本课没有地址转换的路由转发中，路由器向下一链路发送数据时，哪一项正确？

- A. 必须把 IP 目的地址改成路由器出口地址
- B. 链路层重新封装，IP 目的仍然是最终服务器
- C. 原以太网帧的所有字段保持不变
- D. TCP 目的端口必须每经过一跳加一

**答案：B。** 下一链路需要对应的帧地址；普通 IP 转发仍以原目的地址寻找去向。A 混淆最终目的与下一跳，C 忽略重新封装，D 没有协议依据。

## 面试追问

**每个路由器都必须理解 `ADD 2 3` 吗？**

普通网络层转发不需要解释应用语义。某些设备还提供代理、过滤等更高层功能，但不能因此认为路由这一职责本身要求理解所有应用协议。
