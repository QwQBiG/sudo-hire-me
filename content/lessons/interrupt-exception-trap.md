# CPU 为什么会暂时离开当前指令流

## 从三个事件开始，而不是背三个词

设用户程序正在计算：定时器设备发出请求、程序执行一条非法指令、程序主动请求操作系统读取文件。这三件事都可能让处理器转到预设处理入口，但**触发来源和与当前指令的关系不同**。外部中断（Interrupt）通常来自当前指令流之外的设备或定时事件，按处理器规则在合适边界被受理；同步异常（Synchronous Exception）由正在执行的指令产生；系统调用（System Call）是程序有意请求受保护的内核服务，通常经专门指令触发同步控制转移。[RISC-V 特权架构：陷入与特权级](https://docs.riscv.org/reference/isa/priv/priv-intro.html)

陷入（Trap）**不是所有教材里固定独立于“中断”和“异常”的第三类原因**。在 RISC-V 术语里，trap 是异常或中断导致的控制转移总称，`ECALL` 产生同步异常；在 x86 文档中，trap 也可指某类处理器异常，与 fault、abort 并列。面试先说使用哪套术语，最稳定的分法是**外部异步**与**当前指令相关的同步**。[RISC-V 规范：`ECALL`](https://docs.riscv.org/reference/isa/priv/machine.html)、[Intel 软件开发手册：异常分类](https://cdrdv2-public.intel.com/843836/325384-sdm-vol-3abcd-dec-24.pdf)

## 逐步推演

### 第一步：正常执行路径

处理器根据程序计数器（Program Counter，PC）取指、译码、执行。用户态代码不能任意直接执行受保护的内核操作；程序需要文件、网络等服务时，按操作系统接口发起系统调用。此时“程序正常计算”仍在它原来的控制流里。

### 第二步：定时器中断来自当前指令以外

定时器产生中断请求时，CPU 按体系结构定义的受理规则保存必要执行状态、转到处理程序（Handler）。处理程序可让内核更新时间、决定调度，然后按规则返回或切换任务。中断到来与被中断的那条普通计算指令没有必然因果关系，所以称**异步**；不是说它能在任意指令的任意半字节处破坏状态。

```text
用户计算 ──→ 定时器事件待处理 ──→ 保存上下文/进入处理程序 ──→ 恢复或调度
```

### 第三步：指令本身引发同步异常

若处理器遇到非法指令，异常与**这次执行的指令**关联。硬件转到相应处理程序，内核据此处理或终止任务。不能从“异常”二字直接推断一定能恢复，也不能说所有异常都会结束进程；具体取决于异常类型和操作系统策略。[RISC-V 特权规范：异常原因](https://docs.riscv.org/reference/isa/priv/machine.html)

用 C 的 `1 / 0` 来演示“必定触发某个固定硬件异常”不严谨：C 的整数除零表达式属于未定义行为，编译器可作不同处理。本课直接讨论处理器层面的非法指令事件，不混淆语言规则与 ISA 规则。

### 第四步：系统调用也是同步的，但有意发起

执行系统调用指令时，程序主动要求受保护的服务。在 RISC-V 示例中，`ECALL` 产生环境调用异常，进入相应陷入处理；操作系统检查请求和参数，完成允许的操作并按约定返回结果。[RISC-V 特权规范：环境调用异常](https://docs.riscv.org/reference/isa/priv/machine.html)

| 事件 | 来源 | 与当前指令关系 | 典型处理方向 |
| --- | --- | --- | --- |
| 定时器中断 | 定时事件 | 外部异步 | 记时、调度、恢复 |
| 非法指令异常 | 执行的指令 | 同步 | 报告错误、终止或按策略处理 |
| 系统调用 | 程序主动执行调用指令 | 同步 | 验证请求、执行内核服务、返回 |

## 面试回答

外中断通常由当前程序指令流之外的设备或定时事件产生，是异步受理的；异常与正在执行的指令相关，是同步的。系统调用是用户程序有意经专门指令请求内核服务，通常作为同步陷入/异常处理。三者都可能转移到特权处理程序，但来源、是否有意和返回策略不同。`trap` 一词跨架构含义不完全一致：RISC-V 用作异常或中断的总称，x86 还把某种异常类别叫 trap；答题时应声明语境，不把一个术语分类强加给全部机器。

## 与语言异常分开

Java 的 `throw new IOException(...)` 是语言和运行时的异常控制流，不等于 CPU 必然发生某个硬件异常；反过来，硬件页故障也未必直接成为应用可捕获的 Java 异常。操作系统、运行时可能在不同层次间做映射，但不能把名称相同当成机制相同。[Java 语言规范：异常](https://docs.oracle.com/javase/specs/jls/se21/html/jls-11.html)

## 常见错误

- **“所有 trap 都是程序主动系统调用。”** 在 RISC-V 术语里外部中断和同步异常也可导致 trap。
- **“外中断一定由当前指令算错引起。”** 定时器中断与当前指令没有该因果关系。
- **“同步异常必定是程序员故意的。”** 非法指令不是正常请求；系统调用才是有意入口。
- **“语言抛异常就是 CPU 硬件异常。”** 两个抽象层次不能直接等同。

## 选择题

在本课区分事件来源的语境下，哪一项最符合“外部异步中断”？

- A. 程序主动执行系统调用指令
- B. 当前指令被识别为非法指令
- C. 定时器发出请求，处理器按规则转入处理程序
- D. Java 代码执行 `throw new Exception()`

**答案：C。** 定时器事件来自当前指令流之外。A 是主动同步入口，B 与当前指令同步，D 是语言异常而非外部硬件中断。
