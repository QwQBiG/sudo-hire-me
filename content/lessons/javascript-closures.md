# 闭包：函数返回后，计数为什么还在

## 从零理解

作用域（scope）决定某个名字在代码哪些位置可以访问。
JavaScript 的词法作用域（lexical scope）按函数定义的位置组织名称查找，而不是按谁调用它来决定。
函数需要一个名字时，先看本层，再沿着定义时的外层环境查找。
词法环境（lexical environment）可以理解为保存绑定以及外层关系的语言层模型，不必等同于某种固定内存布局。

闭包（closure）是函数与它能访问的词法环境的组合。
内部函数即使被返回到外面，仍可能访问创建它时的外层绑定。
因此，外层函数“返回了”和“它创建的一切状态立即消失了”不是同一件事。
闭包访问的是绑定，不是一律把创建时的值拍成一张不再变化的快照。

## 实验代码

```javascript
function createCounter(start = 0) {
  let count = start;
  return function () {
    count += 1;
    return count;
  };
}

const a = createCounter();
const same = a;
const b = createCounter(10);
console.log(a());
console.log(same());
console.log(b());
console.log(a());
```

`start = 0` 表示未传入这个参数时使用默认值 0。
`return function () { ... }` 返回函数本身；返回时没有执行函数体中的加一。
后面的 `a()` 才调用返回的函数，因此“创建计数器”和“让计数器加一”是两件事。

## 逐步推演

### 第一步：创建第一个计数器

`createCounter()` 创建一份外层绑定，记为环境 E1，其中 count 初始为 0。
返回的函数关联 E1，变量 a 关联这个函数。
工厂函数已返回，但这个函数仍然需要 E1 中的 count，后续调用仍可访问它。

### 第二步：增加别名和独立计数器

`same = a` 没有调用工厂函数，没有创建第二份计数状态。
`createCounter(10)` 则是一次新调用，创建环境 E2，count 初始为 10。

| 变量 | 关联的函数 | 访问的计数绑定 |
| --- | --- | --- |
| a | 第一个返回函数 | E1.count = 0 |
| same | 第一个返回函数 | E1.count = 0 |
| b | 第二个返回函数 | E2.count = 10 |

E1、E2 是推演标记，用于区分两份环境，并不是 JavaScript 中可直接读写的属性。

### 第三步：连续调用 a 和 same

调用 a，把 E1.count 从 0 改成 1，返回 1。
调用 same，仍访问 E1，把同一个 count 从 1 改成 2，返回 2。
两次调用都没有重新执行工厂函数中的 `let count = start`。

### 第四步：调用独立的 b，再回到 a

调用 b，把 E2.count 从 10 改成 11，返回 11；E1.count 仍为 2。
再次调用 a，把 E1.count 从 2 改成 3，返回 3。
能否共享状态，取决于函数关联哪个绑定，不取决于变量名是否相似。

## 预期输出

```text
1
2
11
3
```

把 `const same = a` 改为 `const same = createCounter()`，same 就拥有独立计数状态。
此时预期输出为 `1, 1, 11, 2`，因为对 same 的调用不再更新 a 的 count。
这组改动只改变是否创建新计数器，可以用来检验对共享环境的理解。

## 名字的可见性没有改变

在原实验代码末尾添加下面一行：

```javascript
console.log(count);
```

预期出现引用错误（ReferenceError），因为这段外部代码所在的作用域没有 count 绑定。
闭包让返回的函数访问自己的外层环境，没有把 count 自动变成全局变量。
同样，在外面声明另一个 `let count = 100`，也不会替换计数器内部的那一份 count。

## 闭包与资源保留

当返回的函数仍可被访问时，运行环境要保留其后续执行所需的状态。
如果这些状态间接关联很大的对象，保存函数的时间可能影响对象被回收的时机。
垃圾回收（garbage collection，GC）根据可达性等规则回收对象；闭包不天然等于内存泄漏。
需要检查的是“不再需要的函数是否仍被集合、定时器或其他长期对象引用”。

## 常见错误

- **每次调用 a 都把 count 置零。** 初始化在工厂函数内，调用 a 只执行返回函数的函数体。
- **每个函数变量名都有独立状态。** a 和 same 可以关联同一个函数与环境。
- **返回函数才算闭包。** 返回只是展示闭包的一种方式，其他内部函数也能形成闭包。
- **闭包复制的是初始数值。** 本例连续修改同一绑定，所以能够输出递增结果。
- **调用位置决定读到哪个 count。** 名称查找跟函数定义时的词法关系有关。

## 面试回答

闭包由函数及其可访问的词法环境组成，因此函数可以在外层函数返回后继续访问相应绑定。
同一次工厂调用产生的相关函数可能共享绑定，不同调用通常创建各自的局部绑定。
闭包不会扩大外部代码的名称可见范围，保留闭包也不等于必然发生内存泄漏。

## 选择题

原实验中 `const same = a` 之后，先调用 a 再调用 same，为什么返回 1 和 2？

- A. JavaScript 自动同步所有名为 count 的变量。
- B. 两个名字关联同一函数，函数更新同一份 count 绑定。
- C. same 每次从 a 复制最新的数字。
- D. 工厂函数每次调用 same 时都会重新执行。

**答案：B。** 别名共享函数及其环境。A 不存在这样的全局同步；C 把绑定关联误当成动态复制；D 若重新初始化就无法得到本例的连续计数。

## 面试追问

“怎样让两个按钮共享计数？”让它们调用同一个计数器函数，或来自同一状态环境的操作函数。
“怎样让每个按钮独立计数？”分别调用工厂函数，创建各自的局部绑定。
“返回 `count` 与返回函数有什么差别？”前者返回当时的数值，后者返回可以继续访问并操作绑定的函数。
