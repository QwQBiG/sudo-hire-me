# 先找下一跳，再用 ARP 找 MAC

## 从两个地址开始

互联网协议第 4 版（Internet Protocol version 4，IPv4）负责给数据报写入最终目的 IP；以太网帧只负责当前链路的一次交付。两种“目的地址”回答的问题不同：**数据最终给谁？这一跳先交给谁？**

地址解析协议（Address Resolution Protocol，ARP）在以太网等链路上，把**已经选定的下一跳 IPv4 地址**解析为链路层地址，即这里的媒体访问控制地址（Media Access Control Address，MAC Address）。主机并不是先对任意最终目的 IP 广播 ARP，再决定如何路由；它先根据路由信息选出出口和下一跳。[RFC 826：ARP](https://www.rfc-editor.org/rfc/rfc826.html)；[RFC 1122：主机出站路由](https://www.rfc-editor.org/rfc/rfc1122.html#section-3.3.1)

本课只考虑一台主机、一块以太网接口、一条直连路由和一条默认路由。没有更具体的静态路由、代理 ARP、VLAN 或多网卡；实验里的 MAC 均为虚构地址。真实系统应查询路由表，不能把“同前缀”当成全部路由策略。

## 直连时：问目标主机

本机 `192.168.10.37/27` 的掩码是 `255.255.255.224`，直连网络为 `192.168.10.32/27`，覆盖 `.32` 到 `.63`。目标 `192.168.10.50` 落在这个范围内，因此下一跳就是 `.50`。

若 ARP 缓存没有 `.50` 的映射，本机会在本链路广播“谁拥有 `192.168.10.50`？”；得到应答后，发出的帧可以写成：

| 层次 | 目的地址 | 指向谁 |
| --- | --- | --- |
| IPv4 数据报 | `192.168.10.50` | 最终目标主机 |
| 当前以太帧 | `02:00:00:00:00:50` | 同一台主机的示例 MAC |

广播的是 ARP **请求帧**，不是“把后续所有 IP 数据报都广播出去”。已有有效缓存映射时可以省去本次 ARP 请求；缓存条目本身可能过期或更新，并非永久真理。

## 跨网段时：问网关

把最终目标改为 `192.168.10.70`。在本例 `/27` 配置下，它不在 `.32` 到 `.63` 的直连范围内。默认网关 `192.168.10.33` 在直连网段内；本机选它作为下一跳。

此时缺少缓存条目时，ARP 请求问的是**网关 `192.168.10.33` 的 MAC**，不是远端 `.70` 的 MAC。路由器接收该帧后，再按自己的路由决策重新封装下一跳的链路层帧；本机不需要知道远端主机的 MAC。[RFC 1122：Local/Remote Decision](https://www.rfc-editor.org/rfc/rfc1122.html#section-3.3.1.1)

| 层次 | 本机发出时的目的地址 | 指向谁 |
| --- | --- | --- |
| IPv4 数据报 | `192.168.10.70` | 最终目标主机 |
| 当前以太帧 | `02:00:00:00:00:33` | 默认网关的示例 MAC |

转发时 IPv4 目的地址通常保持为最终目标，而每条以太网链路上的帧目的 MAC 会重新确定。这里暂不考虑网络地址转换、隧道等会改变观察方式的机制。

## 一个前缀改变结论的例子

目标 `.50` 与本机 `.37` 在 `/27` 时都属于 `.32` 到 `.63`；改成 `/28` 后，本机直连范围缩为 `.32` 到 `.47`，`.50` 就要经 `.33` 网关。主机 IP 与最终目标 IP 都没变，变化的是**前缀所决定的直连范围**。

在实验中选择 `.50`，先用 `/27` 走一遍，再切到 `/28`；观察 ARP 目标从 `.50` 变成 `.33`。打开“缓存已有映射”后，路由判断仍然要做，但本次 ARP 请求和应答可以跳过。实验不模拟缓存超时、请求丢失、路由器后续转发或真实网络报文。

## 面试回答

ARP 在当前链路上解析**下一跳 IPv4 地址**对应的 MAC。主机先根据路由选下一跳：直连目标时解析目标 IP；经网关转发时解析网关 IP。跨网段发出的 IP 数据报仍以远端主机为目的，当前以太帧却以网关 MAC 为目的。已有有效 ARP 缓存时，本次不必重新广播请求；多路由等真实情况还要按路由表判断。

## 常见误区

- **“访问任何远端网站都 ARP 查询网站的 MAC。”** 本机只能在当前链路解析下一跳；跨网段通常先查询网关 MAC。
- **“只要最后一段数字接近就是同网段。”** 必须依据配置前缀和路由判断，例如 `.37` 到 `.50` 在 `/27` 直连，在 `/28` 不直连。
- **“MAC 和 IP 目的地址沿整条路径都不变。”** 当前链路帧的目的 MAC 随下一跳改变；本例中的最终 IP 目的地址不变。
- **“ARP 命中缓存就不用路由选择。”** 路由仍决定要取哪一个下一跳的缓存映射。

## 选择题

本机 `192.168.10.37/27` 的默认网关是 `192.168.10.33`，要发送给 `192.168.10.70`。若相关 ARP 缓存为空，本机首先解析哪个 IP 的 MAC？

- A. `192.168.10.37`
- B. `192.168.10.70`
- C. `192.168.10.33`
- D. 广播地址 `192.168.10.63`

**答案：C。** `.70` 不在本机 `.32/27` 直连网络里，下一跳是网关 `.33`，ARP 应解析它。B 混淆最终 IP 目的地与当前链路下一跳；A 是源地址；D 是该子网广播地址，不是本次要解析的主机。

## 面试追问

“ARP 找不到应答怎么办？”本机无法取得该下一跳的链路层地址，就不能按本例路径封装交付；实际重试、超时和报错方式由网络栈实现决定，不要凭 ARP 本身保证可靠交付。

“IPv6 也用 ARP 吗？”不。IPv6 使用邻居发现（Neighbor Discovery）等机制解决相应问题；本课的 ARP 是 IPv4/以太网场景。[RFC 4861：Neighbor Discovery for IPv6](https://www.rfc-editor.org/rfc/rfc4861.html)
