# 进程和线程究竟共享哪些资源

## “共享”要问具体是哪一种状态

线程（Thread）是进程内的执行流。以常见 POSIX 线程和 Linux 进程模型说明，同一进程内线程共享虚拟地址空间、全局变量、堆及进程打开的文件描述符；每条线程有自己的执行寄存器状态、栈和线程局部存储（Thread-Local Storage，TLS）。把“栈私有”说成“栈内存绝对不能被别的线程访问”也不准确：栈在共享地址空间中，通过指针仍可能被别的线程访问，问题是生命周期与同步要正确。[Linux manual：pthreads(7)](https://man7.org/linux/man-pages/man7/pthreads.7.html)

不同进程通常各有虚拟地址空间；`fork` 后父子最初可能看到相同内存字节，却因写时复制（Copy-on-Write，COW）而后续各自修改。**进程隔离不等于所有内核对象都毫无关联**：子进程继承的文件描述符与父进程描述符可以指向同一个**打开文件描述**（Open File Description），因此共享文件偏移量与状态标志。[Linux manual：fork(2)](https://man7.org/linux/man-pages/man2/fork.2.html)

## 逐步推演

### 单线程 P 打开文件并 fork

P 的全局变量 `x=7`，描述符 `fd=3` 指向文件 `ABCD`、当前偏移量 0。P 在仍只有一条线程时执行 `fork` 得到子进程 Q。两进程此时都能读到 `x=7`，但它们的虚拟地址空间彼此独立；两侧各有数值为 3 的描述符，指向同一个打开文件描述。本例不讨论多线程进程中调用 `fork` 的额外限制。

### P 的两条线程修改同一变量

P 随后创建线程 T1、T2。T1 在适当同步下把 `x` 改为 9，T2 在同步后读到 `x=9`；这不是把数据“发送”到另一个进程，而是读同一地址空间。Q 的 `x` 仍为 7，因为父进程后续写入不能直接修改子进程自己的内存副本。不加同步就用普通共享变量跨线程读写，在 C/C++ 等语言里可能构成数据竞争，不能拿任意运行结果当规则。

### Q 读文件，P 的下次读从新偏移开始

假设 Q 用 `fd=3` 读取 `AB`，共享打开文件描述的偏移变为 2；随后 P 中 T2 用继承关系对应的 `fd=3` 读取，读到 `CD`。这不表示 Q 和 P 共享虚拟内存，也不表示两个进程的**描述符表**是同一张表；它们的表项指向了同一个底层打开文件描述。若各自独立执行 `open`，通常会得到各自独立的文件偏移。[Linux manual：open(2)](https://man7.org/linux/man-pages/man2/open.2.html)

## 面试回答

同进程线程通常共享地址空间、堆、全局数据和打开的文件，分别保存寄存器、执行位置、栈与线程局部数据；共享状态访问仍需要同步。不同进程通常有独立虚拟地址空间，`fork` 后的内存修改彼此分离。但资源隔离不能绝对化：父子继承的描述符可引用同一个打开文件描述，因此文件偏移量可能共享。答“进程不共享任何东西”或“线程共享所有东西”都过于绝对。

## 常见误区

- **“线程栈在不同地址空间。”** 同进程线程处在共享地址空间，各自使用不同栈区域。
- **“fork 后变量值相同，所以以后每次写也同步。”** 初始内容相同不等于后续共享写入。
- **“不同进程文件偏移量一定独立。”** 继承或复制的描述符可指向同一个打开文件描述。

## 选择题

单线程进程 P 打开文件后 `fork` 出 Q，两者没有再次 `open`。Q 用继承的 fd 顺序读 2 字节，随后 P 用对应 fd 顺序读。关于读取偏移，哪项最准确？

- A. P 必定仍从偏移 0 读，因为进程地址空间不同。
- B. P 通常从偏移 2 读，因为两个 fd 指向共享的打开文件描述。
- C. Q 读取会直接修改 P 的全局变量。
- D. 只要 fd 都等于 3，任意两个无关进程都共享偏移。

**答案：B。** `fork` 继承的描述符指向同一个打开文件描述；A 混淆文件偏移与虚拟内存，D 忽略“是否同源打开”。
