# SQL：只看满足条件的成绩

## 从零理解

结构化查询语言（Structured Query Language，SQL）用于描述要从关系数据库中读取或修改什么数据。
本课使用 SQLite。表（table）由行和列组成：一行表示一条记录，一列表示某个属性。
`scores(student_id, score)` 表示成绩表有学生编号、成绩两列；不是调用名为 scores 的函数。

本课只查询一张表。先讲明“要哪些记录、看哪些列、按什么顺序”，再把需求变成 SQL。
例如“列出不低于 80 分的成绩，高分在前”，包含筛选条件 `score >= 80` 和降序排序。
查询会返回结果表，不会因此把原成绩表重新排列或删除不合格成绩。

## 输入数据

| student_id | score |
| --- | --- |
| 1 | 80 |
| 1 | 90 |
| 2 | 60 |

学生 1 的两条记录分别代表两次成绩。此时不能因为编号重复，就断言有一行是错误数据。
预置的学生表还有学生 3，但成绩表没有该学生的记录；单独查询成绩表不会自动补出该学生。
需要保留没有成绩的学生时，下一课会通过左连接关联两张表。

## 实验代码

```sql
SELECT student_id, score
FROM scores
WHERE score >= 80
ORDER BY score DESC, student_id ASC;
```

`SELECT` 指定输出列；`FROM` 指定来源；`WHERE` 指定保留条件；`ORDER BY` 指定排序。
`DESC` 来自 descending，表示降序；`ASC` 来自 ascending，表示升序，也是默认方向。
第二个排序键只在第一个键相同时参与比较，不会推翻不同成绩之间的顺序。

## 逐步推演

### 第一步：确定来源

从 `scores` 得到三条候选记录 `(1,80)`、`(1,90)`、`(2,60)`。
此时还不能输出答案，因为筛选条件和排序尚未落实。

### 第二步：逐行判断条件

| 候选记录 | score >= 80 | 是否保留 |
| --- | --- | --- |
| (1,80) | 真 | 是 |
| (1,90) | 真 | 是 |
| (2,60) | 假 | 否 |

筛选后有两行；“不低于”包含等于，所以 80 必须保留。
若误写 `score > 80`，就会少返回这一行。

### 第三步：形成输出并排序

输出学生编号和成绩两列。按照成绩降序，90 在 80 之前。
结果为 `(1,90)`、`(1,80)`，学生编号在两行相同，因此第二排序键不改变本次结果。
这是逻辑推演，数据库可以用不同执行计划实现同一查询，不必真的逐行按此顺序操作。

## 预期结果

| student_id | score |
| --- | --- |
| 1 | 90 |
| 1 | 80 |

不写 `ORDER BY` 时，不保证按插入顺序、学生编号顺序或上一次显示顺序返回。
若所有排序键都相同，行之间仍可能并列；需要唯一顺序时，应增加能区分记录的键。

## NULL 为什么不能直接比较

`NULL` 表示缺失或未知，不是数字 0，也不是空字符串。
未知的成绩可能高也可能低，因此 `NULL >= 80` 不能被判为真或假，结果仍是 `NULL`。
SQL 条件可以涉及真、假、未知；`WHERE` 只保留结果为真的行。

```sql
SELECT NULL >= 80 AS comparison,
       NULL = NULL AS equality,
       NULL IS NULL AS missing;
```

在 SQLite 中，预期结果依次为 `NULL`、`NULL`、`1`；这里用整数 1 表示真。
`AS` 为输出列起别名。判断缺失用 `IS NULL`，判断非缺失用 `IS NOT NULL`。
如果要同时保留“达标”和“尚未录入”的成绩，可以用 `score >= 80 OR score IS NULL`。

## 常见错误

- `WHERE score = NULL` 不能找出未知成绩，因为等号比较结果不是“真”。
- `WHERE score <> 80` 也不会自动保留 NULL；“不等于 80”与“未知”不是同一判断。
- `SELECT *` 是选择全部列，不是统计条数，也不会去重。
- 文本值写成 `'Lin'`；列名不是带引号的字符串常量，不能写成 `'score' >= 80`。
- 显示顺序与实际存储顺序不同；只看某次结果有序不能证明查询保证有序。

## 面试回答

单表查询用 `FROM` 确定来源，`WHERE` 保留条件为真的记录，`SELECT` 指定输出列，`ORDER BY` 规定结果顺序。
SQL 描述结果要求，逻辑处理过程不等于引擎唯一的物理执行顺序。
NULL 表示缺失或未知，普通比较通常得到未知；判断缺失应使用 `IS NULL`。

## 选择题

某行的 `score` 为 NULL，以下哪个条件会把这一行保留下来？

- A. `score = NULL`
- B. `score <> NULL`
- C. `score >= 0`
- D. `score IS NULL`

**答案：D。** `IS NULL` 专门判断缺失值，所以结果为真。A、B 的普通比较产生未知；C 不能从未知成绩推出非负。`WHERE` 不保留结果为未知的行。

## 面试追问

“筛选不低于 80 分，再按分数升序”应改哪里？把 `DESC` 改成 `ASC`，保留 `>= 80`。
“同一个学生出现两行是否应该 DISTINCT？”先确认一行代表什么；两次不同成绩是不同事实，去重不能代替业务含义。
“零分和缺考能不能都写 0？”可以制定这样的业务规则，但会失去区分两者的信息；数据模型应明确表达要保留的含义。
