# 进程状态怎样转换

## 先问“能运行吗”，再问“正在运行吗”

本课用常见的五状态教学模型：在运行（Running）、就绪（Ready）、阻塞/等待（Blocked/Waiting）三种执行状态之外，加上新建（New）和终止（Terminated）两个生命周期边界。**就绪**表示具备执行条件、只等 CPU；**运行**表示当前真正占有 CPU；**阻塞**表示等待某个外部条件，例如磁盘 I/O 完成，就算 CPU 空闲也不能继续这条执行流。OSTEP 着重展示其中三种执行状态；实际操作系统可能以线程为调度实体、有更多内部状态，不必与五个标签一一对应。[OSTEP：The Abstraction: The Process](https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-intro.pdf)

## 把一次读取放进状态图

假设进程 P 创建后可运行：`新建 → 就绪`。调度器选中它：`就绪 → 运行`。P 调用一个需要等待数据的读取操作：`运行 → 阻塞`。数据到达后，P 先变成**就绪**，不是立即变成运行；等调度器再次选择它，才 `就绪 → 运行`。如果运行中的 P 用完时间片、仍有工作且无需等待，则可 `运行 → 就绪`。完成后 `运行 → 终止`。[OSTEP：Process States](https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-intro.pdf)

| 事件 | 合法的本课转换 | 原因 |
| --- | --- | --- |
| 创建完成 | 新建 → 就绪 | 有执行条件，等待 CPU |
| 获得 CPU | 就绪 → 运行 | 调度器选中它 |
| 等待 I/O | 运行 → 阻塞 | 所需数据暂不可用 |
| I/O 完成 | 阻塞 → 就绪 | 条件满足，但尚未分到 CPU |
| 时间片结束 | 运行 → 就绪 | 可继续运行，轮到别人 |
| 执行完成 | 运行 → 终止 | 不再参加调度 |

实验让你按事件推进单个进程，并在每步看它所在的状态。若尝试“阻塞时直接抢占时间片”，模型会拒绝，因为它本来就没有在 CPU 上运行；这是**事件前提不满足**，不表示所有操作系统都采用同一状态命名。

## 区分主动等待和被抢占

两者都使进程离开 CPU，后续却不同：主动等待 I/O 进入阻塞，等待的是数据；被抢占进入就绪，等待的是 CPU。就绪队列中已有 A，P 的 I/O 恢复后加入就绪队列，A 仍可能先运行。说“唤醒 = 运行”会跳过一次调度决定。[Linux manual：sched(7)](https://man7.org/linux/man-pages/man7/sched.7.html)

## 面试回答

在常见五状态教学模型里，新建表示正在建立执行实体，就绪表示已具备运行条件但在等 CPU，运行表示正在执行，阻塞表示在等 I/O 等事件，终止表示完成。调度使就绪到运行；时间片到使运行回就绪；等待事件使运行到阻塞；事件完成通常先回就绪，不能直接认定已运行。真实内核状态和调度粒度可能不同，答题要先说明采用的模型。

## 常见误区

- **“CPU 空闲，阻塞进程就能立即跑。”** 它还在等自身所需事件。
- **“I/O 完成就正在运行。”** 只恢复运行资格，是否分到 CPU 另由调度决定。
- **“被抢占和等待 I/O 都是阻塞。”** 被抢占但可继续执行的是就绪。

## 选择题

P 正等待磁盘读取，数据刚到达；调度器尚未选择 P。按本课模型，P 此时是什么状态？

- A. 新建
- B. 就绪
- C. 运行
- D. 终止

**答案：B。** 数据到达消除了等待条件，P 可以运行但尚未取得 CPU；C 把唤醒当成调度。
