# 贪心入门：最多能排几个活动

## 一个看起来容易选错的问题

给出若干活动，每项用半开时间段 `[开始,结束)` 表示；结束时间等于另一个开始时间时，两项可以连续安排。目标是选出**数量最多**、彼此不重叠的活动。例子：

| 活动 | 时间段 |
| --- | --- |
| A | `[0,5)` |
| B | `[1,2)` |
| C | `[2,3)` |
| D | `[3,4)` |
| E | `[4,5)` |

“最早开始就先选”会先选 A，只得到 1 项；选 B、C、D、E 可以得到 4 项。贪心算法（Greedy Algorithm）不是“随便选当前看起来好的一项”，而是针对**特定目标**选择一条可以证明不会损失最优解的规则。

对这个“不带权、最大数量”的区间调度问题，正确规则是**优先结束最早的活动**：它最早释放后面的时间。先按结束时刻排序，逐项检查开始时刻是否 `≥` 已选最后一项的结束时刻；是就加入，否则跳过。

## 逐步推演

### 排出候选顺序

按结束时刻排序，结束时间依次为 2、3、4、5、5；在同为 5 时按开始时刻排序，本课顺序为 `B,C,D,A,E`。已选集合 `[]`，可用时间起点视为负无穷。

### 先选 B

B 在 `[1,2)`，最早结束；选后集合 `[B]`，最后结束时刻为 `2`。C 的开始时刻正好是 `2`，所以按半开区间约定可衔接。

### 衔接 C 与 D

C `[2,3)` 满足 `2≥2`，加入后 `[B,C]`、最后结束 `3`；D `[3,4)` 满足 `3≥3`，加入后 `[B,C,D]`、最后结束 `4`。

### 拒绝 A，再选 E

A 虽然到 5 才结束，但开始 0 小于最后结束 4，会与已选活动冲突，跳过。E `[4,5)` 满足 `4≥4`，得到 `[B,C,D,E]`，共 4 项。

### 检查“最早开始”反例

如果另一条规则先挑 A `[0,5)`，B、C、D、E 均与 A 重叠，只能得到 `[A]` 一项。这一反例足以否定“最早开始一定最优”，但还不能单靠一个例子证明“最早结束总最优”。

## 为什么最早结束不会吃亏

设当前还没安排的活动里，贪心选了结束最早的 `g`。考虑某个最优方案的第一项 `o`。因为 `g` 是最早结束，`finish(g)≤finish(o)`；用 `g` 替换最优方案中的 `o`，后面原本能接在 `o` 之后的活动，仍能接在更早或同时结束的 `g` 之后。于是存在一个最优方案以 `g` 开头。对剩余可衔接活动重复此论证，逐步得到贪心解。这个**交换论证**比“看起来空出更多时间”更完整。

输入有 `n` 项，排序 `O(n log n)`，一次扫描 `O(n)`，总时间 `O(n log n)`。若输入已经按结束时刻排序，扫描本身是 `O(n)`。除存储排序副本和答案外，扫描状态只需最后结束时刻。

## 面试回答

在不带权的“最多安排多少个互不重叠活动”问题中，按结束时间升序排序，每次选开始时间不早于上个已选结束时间的活动。最早结束的选择可通过交换论证替换某个最优解的第一项，不降低最优解数量；递归到后续活动，因此正确。排序加扫描时间 `O(n log n)`；如果活动有不同权重或目标改成总收益最大，这条贪心规则不再保证最优。

## 多语言示例

两段程序都输入上述五项活动，预期输出 `B C D E`。代码用 `[start,end)` 的可衔接条件 `start >= last_end`，并在结束时间相同处按开始时间排序，结果可复现。

### C++

```cpp
#include <algorithm>
#include <iostream>
#include <limits>
#include <vector>

struct Job { char name; int start, finish; };

int main() {
    std::vector<Job> jobs{{'A',0,5},{'B',1,2},{'C',2,3},{'D',3,4},{'E',4,5}};
    std::sort(jobs.begin(), jobs.end(), [](const Job& a, const Job& b) {
        if (a.finish != b.finish) return a.finish < b.finish;
        return a.start < b.start;
    });
    int last_end = std::numeric_limits<int>::min();
    for (const Job& job : jobs) {
        if (job.start >= last_end) {
            std::cout << job.name << ' ';
            last_end = job.finish;
        }
    }
    std::cout << '\n';
}
```

### Python 3

```python
jobs = [('A', 0, 5), ('B', 1, 2), ('C', 2, 3), ('D', 3, 4), ('E', 4, 5)]
last_end = float('-inf')
chosen = []
for name, start, finish in sorted(jobs, key=lambda job: (job[2], job[1])):
    if start >= last_end:
        chosen.append(name)
        last_end = finish
print(' '.join(chosen))  # B C D E
```

## 改了目标，规则也可能失效

假设 A `[0,5)` 收益 100，而 B、C、D、E 各收益 1。按最早结束选四项，总收益 4；只选 A 收益 100。如果目标改成“收益最大”，本课的最早结束规则就不正确，通常要重新建模为带权区间调度的动态规划。面试时先问清是“数量最多”还是“收益最大”，这会决定算法。

## 选择题

对本课不带权活动选择问题，为什么优先最早结束，而不是最早开始？

- A. 因为最早结束规则在任何贪心问题都正确
- B. 因为最早开始的 A 会挡住四个短活动，而最早结束可以通过交换论证保持最优数量
- C. 因为活动按字母顺序排列
- D. 因为结束时间不能相同

**答案：B。** A 把具体问题扩大成错误的普遍命题；C 与目标无关；D 与本例不符，A、E 都在 5 结束。
