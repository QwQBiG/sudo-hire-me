# 浮点数：为什么 0.1 不能原样存成 binary32

## 从一个可精确表示的分数开始

在十进制中，`0.5 = 1/2`；写成二进制是 `0.1₂`，因为小数点后第一位的权重是 `1/2`。`0.25 = 1/4 = 0.01₂` 也能在有限位结束。

十进制 `0.1 = 1/10` 却不同：任何有限二进制小数都能写成 `整数 / 2ᵏ`。如果 `1/10` 等于某个 `整数 / 2ᵏ`，就会有 `10 × 整数 = 2ᵏ`；左边含因子 5，右边只含因子 2，矛盾。所以**无论给多少有限位，都无法精确存下十进制 0.1**。这不是某种语言独有的 bug，而是进制和有限长度共同造成的限制。[Python 官方教程：浮点表示误差](https://docs.python.org/3/tutorial/floatingpoint.html)

## binary32 存什么

IEEE 754 binary32 常称单精度（Single Precision），总长 32 位。对于**非零、有限、正规数**，布局是 `1 位符号 | 8 位指数字段 | 23 位小数字段`。正规数还隐含一个最高位 `1`，所以有效数字有 **24 位二进制精度**，并不是只有 23 位。

| 字段 | 本课含义 | 0.1 的字段 |
| --- | --- | --- |
| 符号位（Sign Bit） | `0` 为正，`1` 为负 | `0` |
| 指数字段（Exponent Field） | 正规数的实际指数加偏置 `127` | `01111011`，即 123 |
| 小数字段（Fraction Field） | 隐含前导 `1` 后的 23 位 | `10011001100110011001101` |

对这里的正规数，值按 `(-1)^符号 × (1 + 小数字段对应的二进制小数) × 2^(指数字段数值 - 127)` 计算。**这个公式有条件**：指数字段全 0 时包括零和非正规数（Subnormal Number），没有隐含前导 `1`；全 1 时可表示无穷大或非数（Not a Number，NaN），不能照此公式代入。[Java `Float` 位布局与特殊值](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Float.html#floatToIntBits(float))

## 逐步推演

### 第一步：把 1/10 写成二进制小数

用“乘 2 取整数位”：`0.1×2=0.2` 得 0；`0.2×2=0.4` 得 0；`0.4×2=0.8` 得 0；`0.8×2=1.6` 得 1，留下小数 `0.6`。继续得到 `0.6×2=1.2` 得 1、`0.2×2=0.4` 得 0、`0.4×2=0.8` 得 0、`0.8×2=1.6` 得 1，之后 `0011` 重复。

因此 `0.1₁₀ = 0.00011001100110011…₂`。省略号表示无限重复，不表示末尾可以忽略而仍精确。

### 第二步：写成正规数形式

把二进制小数点向右移 4 位，得到 `1.1001100110011…₂ × 2⁻⁴`。数值小于 1，所以实际指数是 `-4`；加 binary32 的偏置 `127`，存入指数字段的整数是 `123 = 01111011₂`。

0.1 为正，符号位为 `0`。此时已经得到 `0 | 01111011 | ...`，但尾部循环不能无限写入 23 位小数字段。

### 第三步：舍入到 23 位小数字段

本例按 IEEE 754 的默认舍入模式“最接近值，恰好居中时取偶数”（Round to Nearest, Ties to Even）转换为 binary32。保留 23 位小数后，重复序列还没有结束，必须考虑后续位；最接近的可表示值是向上舍入得到的小数字段 `10011001100110011001101`。

完整 32 位为 `0 | 01111011 | 10011001100110011001101`，按 4 位一组改写成十六进制为 **`0x3DCCCCCD`**。这是一种 binary32 的位模式；它不是把十进制字符串 `"0.1"` 直接存进 4 字节。

### 第四步：算出存下来的真实数值

隐含的首位 `1` 加 23 位小数字段，对应一个 24 位整数 `2²³ + 0x4CCCCD = 13,421,773`。实际指数为 `-4`，所以储存的值是：

`13,421,773 × 2⁻²³ × 2⁻⁴ = 13,421,773 / 2²⁷ = 0.100000001490116119384765625`。

它比数学上的 `1/10` 稍大。binary32 可以存下这个**近似值本身**，但无法存下原来的十进制 `1/10`。输出显示成 `0.1` 或较短小数时，通常又经过十进制格式化；显示文本不等于存储的精确值。

### 第五步：用明确的格式检验位模式

Python 3 标准库 `struct` 的 `>f` 明确使用大端 binary32 格式。把输入 `0.1` 打包成四个字节，再解包并取精确分数；`format` 只决定**显示格式**，不改变读回的数值。

```python
import struct
from fractions import Fraction

raw = struct.pack(">f", 0.1)
value = struct.unpack(">f", raw)[0]
print(raw.hex())
print(Fraction(value))
print(format(value, ".17g"))
```

```text
3dcccccd
13421773/134217728
0.10000000149011612
```

最后一行只打印了 17 位有效数字；分数与第四步的长十进制才是该 binary32 数值的精确表示。Python 3 的 `struct` 对 `f` 使用 IEEE 754 binary32，与机器的原生浮点存储选择无关。[Python 官方文档：struct 浮点格式](https://docs.python.org/3/library/struct.html#format-characters)

## 面试回答

IEEE 754 binary32 的正规有限数用 1 位符号、8 位带偏置指数和 23 位小数字段表示，隐含前导 `1` 使有效精度为 24 位。有限二进制小数的分母只能是 2 的幂，而十进制 `0.1 = 1/10` 的分母含因子 5，所以不能有限表示；binary32 在默认舍入模式下选取附近的 `0x3DCCCCCD`，实际值是 `13,421,773 / 2²⁷`。显示为 `0.1` 不代表内部恰好等于 `1/10`。零、非正规数、无穷大和 NaN 不套用正规数的隐含前导 `1` 公式。

## 常见错误

- **“浮点数不能准确存任何小数。”** `0.5 = 1/2`、`0.25 = 1/4` 都可以有限二进制表示；问题取决于具体分数。
- **“binary32 只有 23 位精度。”** 它显式存 23 位小数字段，但正规数还包含隐含前导 `1`，有效数字共 24 位。
- **“任何语言里写 `0.1` 都会得到本节同一个 32 位位模式。”** 还要先确定实际浮点格式与转换规则；例如普通 JavaScript `Number` 使用 binary64，具体位模式和误差与 binary32 不同。
- **“打印出 0.1 就说明存的是精确 0.1。”** 格式化会选取便于阅读的短字符串，不能由显示长度反推内部位值。

## 选择题

关于 IEEE 754 binary32 的**正规有限数**，哪项正确？

- A. 小数字段存 23 位，隐含前导 1 后有效数字为 24 位
- B. 指数字段全 0 时仍按隐含前导 1 解释
- C. 十进制 0.1 可以写成有限二进制小数
- D. 显示为 `0.1` 就证明存储值严格等于 `1/10`

**答案：A。** 23 位小数字段加正规数的隐含前导 1 构成 24 位精度。B 忽略非正规数与零的特殊规则；C 与 `1/10` 分母含因子 5 矛盾；D 把十进制显示误当成内部精确值。

## 面试追问

**金额计算为什么常用十进制定点数或整数分单位？** 如果需求要求以十进制最小单位精确记账，选择能精确表达该单位的表示方式更合适；二进制浮点对于 `0.1` 等十进制小数可能先产生表示误差。不过任何数值类型仍需明确取值范围、舍入规则和溢出处理，不能只换一个类型就认为全部计算自动正确。
