# Rust：move 之后，字符串被释放了吗？

## 从零理解

绑定（binding）是名字与值之间的关联。例如 `let a = String::from("hello")` 创建字符串并由 `a` 持有。
所有权（ownership）决定值的持有和清理责任；移动（move）转移这个值，借用（borrow）通过引用访问它，克隆（clone）按类型约定创建副本。
`String` 管理可以动态调整的字符串缓冲区，清理资源需要明确责任。
若两个对象都把同一份资源当成自己独占管理的资源，并且分别释放，就可能产生重复释放问题。
Rust 通过所有权和借用规则约束访问与清理责任，在编译时拒绝相应的非法使用。

在本课的普通局部变量例子中，未被继续移动出去的拥有者在作用域结束时清理所拥有的值；这不保证进程被强制终止等情况下也运行析构。
移动的重点是语言层面的使用权限和责任变化，不能据此断言机器底层必定搬运了哪些字节。

## 先判断是否能编译

```rust
fn main() {
    let a = String::from("hello");
    let b = a;
    println!("{a}");
}
```

`let b = a` 按值使用 `a` 持有的 `String`；该类型没有实现 `Copy`，这里发生移动。
之后 `b` 持有该值，而打印语句又尝试读取 `a` 中已经移出的值，因此被编译器拒绝。
问题不是“字符串变成空串”，而是原位置已不能这样使用。

## 参考编译诊断

下面仅摘录典型诊断的核心信息；编译器版本会影响排版和提示细节。

```text
error[E0382]: borrow of moved value: `a`
```

这是编译阶段的错误，不是运行时异常；该程序没有成功编译，因此没有打印输出。
下面的状态表是规则推演，不能当成上述错误程序已经实际执行的记录。

| 语句 | 按所有权规则推演的状态 |
| --- | --- |
| 创建 `a` | `a` 持有字符串值并承担清理责任 |
| `let b = a` | 值移动到 `b`，`a` 不能再使用被移出的值 |
| 尝试打印 `a` | 违反使用规则，编译不通过 |

## 用借用读取，用克隆复制

下面是可编译的参考例子；长度函数只需要读字符串，因此接收 `&str`。

```rust
fn length(text: &str) -> usize {
    text.len()
}

fn main() {
    let a = String::from("hello");
    let b = a;
    println!("{}", length(&b));
    let mut c = b.clone();
    c.push('!');
    println!("{b}");
    println!("{c}");
}
```

`length(&b)` 借用 `b` 的内容；这里的 `&String` 可以按函数参数要求转换为 `&str`。
函数没有取得 `String` 的所有权，返回后 `b` 仍持有字符串，仍能继续使用。
`b.clone()` 为这个 `String` 创建独立的内容副本，因此修改 `c` 不会同时改变 `b`。`mut c` 允许修改字符串，`push('!')` 在末尾添加一个字符。

## 参考输出

```text
5
hello
hello!
```

这里 `len()` 返回 UTF-8（Unicode Transformation Format, 8-bit）编码的字节长度。
`hello` 中的字符属于美国信息交换标准代码（American Standard Code for Information Interchange，ASCII），在 UTF-8 中各占一个字节；中文字符串的字节数不等于汉字数。
函数结束时，这个例子中的 `b` 与 `c` 分别清理自己拥有的字符串；`a` 不会再清理已移走的值。

## 再比较三种操作

| 操作 | 原字符串还能否使用 | 是否得到独立内容副本 |
| --- | --- | --- |
| `let b = a`，其中 a 是 `String` | 不能再使用 a 中被移出的值 | 否 |
| `let r = &a` | 拥有者仍是 a，访问须满足借用规则 | 否 |
| `let b = a.clone()` | 可以继续使用 a | 对本课的 String 是 |

借用期间不能任意修改被借用数据；在安全 Rust 的基础规则下，活跃共享借用与独占可变借用受到互斥约束。
借用的有效期可能在最后一次使用后结束，不一定持续到整个花括号结束。
如果把 `String` 换成 `i32`，简单赋值可以隐式复制，因为 `i32` 实现了 `Copy`。

## 常见错误

- **“move 就是 drop。”** move 转移所有权；销毁是另一个操作，移动时不会因此释放字符串内容。
- **“所有赋值都会移动。”** 要看类型；普通整数等 `Copy` 类型的按值使用可以隐式复制。
- **“借用让函数获得拥有权。”** 引用提供访问能力，不把原 `String` 的清理责任交给只读函数。
- **“clone 总是深复制所有东西。”** 本课结论针对 `String`；其他类型的克隆语义由该类型决定。
- **“给引用写生命周期标注，就能让对象活得更久。”** 标注表达有效期约束，不延长实际对象的存活时间。

## 面试回答

Rust 的所有权规则决定值由谁持有，以及资源由谁负责清理。
对 `String` 这样的非 `Copy` 类型，`let b = a` 会移动值，原绑定不能继续使用被移出的值；移动不等于销毁或复制全部内容。
借用用引用访问原值，不转移原值的所有权；`String::clone` 创建可独立修改的字符串副本。

## 选择题

对于 `let a = String::from("hello"); let b = a;`，哪个说法正确？

- A. 第二句立即释放字符串，所以 a 和 b 都不能使用。
- B. a 和 b 各有一份独立字符串，修改其中一个不会影响另一个。
- C. b 只是 a 的共享引用，a 仍负责清理。
- D. b 持有移入的字符串值，a 不能继续使用被移出的值。

**正确答案：D。**

- A 把移动和销毁混为一谈；字符串并没有在第二句被立即释放。
- B 描述的是本课 `String::clone` 产生副本后的效果，不是移动。
- C 描述了借用的部分含义，但这段代码没有创建 `&a`。
- D 正确，说明了所有权变化和原绑定的使用限制。

## 面试追问

如果函数只读取字符串长度，参数采用 `String` 与 `&str` 分别意味着什么？
参考思路：前者按值接收，传入原 `String` 会移动它；后者借用内容，调用方保有字符串。
若函数需要保存并拥有字符串，则取得所有权可能合理；应按接口职责选择，而不是遇到错误就加 `clone()`。
