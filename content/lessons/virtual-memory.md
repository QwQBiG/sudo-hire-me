# 虚拟内存与地址转换

## 面试回答

虚拟内存（Virtual Memory）为进程提供独立的地址空间，借助地址映射与权限检查管理它对物理存储的访问。分页（Paging）把虚拟空间分成固定大小的页，并通过页表映射到物理页框。虚拟地址由页号和页内偏移组成，转换时替换页号对应的页框号，偏移不变。按需调页允许合法页面暂时不驻留内存；发生缺页后，系统可能补齐映射再继续，也可能判定访问非法。虚拟内存不等于交换区，更不保证内存需求可以无限扩大。

## 从零理解两种地址

程序里的指针通常指向虚拟地址（Virtual Address，VA），不是直接指向某根内存条的位置。物理地址（Physical Address，PA）用于定位物理地址空间中的位置；本课只讨论映射到普通内存的情况。

内存管理单元（Memory Management Unit，MMU）按照系统配置执行地址转换与保护检查。操作系统负责建立和维护映射；不能理解为每次普通内存访问都要调用一次操作系统函数。

两个进程都访问虚拟地址 `2500`，可以被转换到不同的物理地址。地址空间独立不意味着物理页绝不共享；是否共享、写入是否互相可见，取决于具体映射规则。例如写时复制（Copy-on-Write，COW）可以先共享物理页，在需要修改时再复制，不等于两个进程可以直接修改对方的数据。[Linux fork 的写时复制说明](https://man7.org/linux/man-pages/man2/fork.2.html)

## 页、页框和页表各是什么

| 概念 | 含义 | 本课模型 |
| --- | --- | --- |
| 虚拟页（Page） | 虚拟空间中固定大小的一段 | 每页 1024 字节 |
| 物理页框（Page Frame） | 物理内存中容纳一页的空间 | 与页大小相同 |
| 页表（Page Table） | 记录映射与控制信息的数据结构 | 以虚拟页号查找条目 |
| 页表项（Page Table Entry，PTE） | 一条映射记录 | 包含页框号及权限等信息 |

下面使用 **16 位虚拟地址、1024 字节页面、单级页表** 的教学模型。真实系统常采用其他页大小和多级页表；示例中的“合法”和“驻留”是便于理解的逻辑信息，不表示硬件一定提供两个同名位。

因为 `1024 = 2^10`，页内偏移需要 10 位；16 位地址剩下 6 位用于虚拟页号。

## 逐步推演

### 第一步：把地址拆成页号与偏移

进程 P 要读取虚拟地址 `2500`。页号从 0 开始，每页 1024 字节：

```text
2500 = 2 × 1024 + 452
虚拟页号 = 2
页内偏移 = 452
```

页 2 覆盖地址 `2048..3071`，所以 `2500` 落在页 2 中，距该页起点 452 字节。偏移合法范围是 `0..1023`，不能取到 1024。

### 第二步：按当前进程的映射查页表

假设对应的地址转换尚未缓存，需要查询页表。系统为 P 管理的相关映射如下：

| 虚拟页号 | 是否属于合法区域 | 当前是否驻留 | 物理页框 | 允许操作 |
| --- | --- | --- | --- | --- |
| 2 | 是 | 是 | 5 | 读、写 |
| 3 | 是 | 否 | 暂无 | 读、写 |
| 7 | 否 | 否 | 无 | 无 |

读取页 2 满足权限且页面驻留，得到页框 5。另一个进程即使也有“页 2”，也要使用自己的映射信息，不能直接复用 P 的这条记录。

### 第三步：保留偏移，拼出物理地址

页框 5 的起始物理地址为 `5 × 1024 = 5120`，再加原来的偏移：

```text
物理地址 = 页框号 × 页大小 + 页内偏移
         = 5 × 1024 + 452
         = 5572
```

变的是所在页面的位置，不变的是数据在页内的位置。若错误地将页号 2 当成页框号，就会得到原虚拟地址，等于没有完成转换。

### 第四步：换一次访问，观察缺页处理

现在 P 读取虚拟地址 `3500 = 3 × 1024 + 428`，对应合法但未驻留的页 3。

| 阶段 | 状态变化 |
| --- | --- |
| 查映射 | 页 3 当前不能直接完成访问，触发缺页异常 |
| 系统检查 | 该地址属于允许读取的区域，判断能否补齐页面 |
| 建立映射 | 假设分配页框 9，准备好数据并更新映射 |
| 重试访问 | 使用 `9 × 1024 + 428 = 9644` 作为物理地址 |

“准备数据”可能是读取文件或交换区，也可能是为新分配页面提供零值，并不必然访问磁盘。若访问的是非法页 7，系统不能按上述方式把任意地址都变成合法内存。

## TLB 未命中为什么不是缺页

地址转换后备缓冲器（Translation Lookaside Buffer，TLB）缓存近期使用的地址转换信息，常被称为快表。它缓存的是映射，不是普通变量的全部数据。

| 情况 | 还缺什么 | 是否必然读磁盘 |
| --- | --- | --- |
| TLB 未命中，页表中有可用映射 | 需要找到并缓存映射 | 否 |
| 合法页面尚未驻留 | 需要系统准备页面 | 否，取决于页面来源 |
| 访问违反保护规则 | 需要系统处理访问异常 | 否，可能直接报告错误 |

TLB 未命中由硬件遍历页表还是由软件辅助处理，取决于体系结构；不能把所有平台都写成同一条固定流程。

## 地址空间大，为什么不等于可用内存多

16 位虚拟地址在本模型中可以编码 `2^16 = 65536` 个字节位置，但不表示每个地址都合法，也不表示每个位置都已有独占的物理页框。

分页允许各页分散放置，避免要求整个进程在物理内存中连续。代价包括页表占用、转换成本和页内未用空间；频繁调页还可能使程序明显变慢。

## 常见误解

- **“没有交换区，就没有虚拟内存。”** 地址映射、保护和共享并不依赖启用交换区。
- **“缺页就是访问了非法地址。”** 按需分配等合法访问也可能触发缺页处理。
- **“页表保存的是程序数据。”** 页表主要保存映射和控制信息，程序数据在被映射的页面中。
- **“TLB 命中后就能忽略权限。”** 缓存的转换仍然受到相应访问权限约束。

## 选择题

页大小为 1024 字节，虚拟地址 2500 所在页映射到物理页框 5。若访问合法，物理地址是多少？

- A. 2500
- B. 5120
- C. 5572
- D. 7500

**答案：C。** `2500 ÷ 1024` 的商是 2，余数是 452；查页表得到页框 5，因此为 `5 × 1024 + 452 = 5572`。A 没做转换，B 丢掉偏移，D 把页号或地址错误相加。

## 面试追问

**虚拟地址 4095 也映射到页框 9 时，物理地址是多少？**

`4095 = 3 × 1024 + 1023`，所以结果为 `9 × 1024 + 1023 = 10239`。它是该页框的最后一个字节，下一字节需要查下一虚拟页的映射。

**为什么多级页表可能节省空间？**

大地址空间往往只有部分区域使用。分层后可按需建立下级页表，减少未使用区域对应的表项存储；代价是未缓存的转换可能需要访问多级结构。
