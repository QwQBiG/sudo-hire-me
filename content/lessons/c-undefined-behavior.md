# C 的未定义行为：别猜它会打印什么

## 三种容易混淆的说法

这里以 ISO C11 为基准。未定义行为（Undefined Behavior，UB）指标准对该行为**不施加任何要求**；不能推断它一定崩溃、返回某个垃圾值或被编译器“自动修好”。未指定行为（Unspecified Behavior）则是在标准允许的若干选择中实现可任选，未必需要记录选了哪一个；实现定义行为（Implementation-Defined Behavior）同样存在实现选择，但实现必须记录其选择。[ISO C N1570：3.4 行为定义](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)

| 问题 | 分类 | 面试中该怎样说 |
| --- | --- | --- |
| 读取 `int a[2]` 的 `a[2]` | 未定义行为 | 索引超出有效元素范围，不能预测结果 |
| 两个互不依赖的函数实参先算哪一个 | 未指定的求值顺序 | 不应依赖固定的先后顺序 |
| 当前实现的 `sizeof(int)` 是多少字节 | 实现定义的类型表示范围的一部分 | 查目标实现文档或运行时测量，不能硬背 4 |

表中第二项只说**互不依赖**的实参；如果写入同一对象等引入额外求值冲突，还可能变成 UB，不能靠此表为任意副作用表达式开脱。第三项更精确地说，C 的整数类型大小、表示和对齐有标准约束，具体实现需定义其选择。[ISO C N1570：6.5 表达式、5.2.4.2 数值限制](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)

## 只演示安全版本

```c
#include <stdio.h>

int main(void) {
    int a[2] = {7, 9};
    size_t index = 2;
    if (index < sizeof a / sizeof a[0]) {
        printf("value=%d\n", a[index]);
    } else {
        puts("index out of range");
    }
    return 0;
}
```

预期输出是 `index out of range`。数组仅有下标 0 和 1；`index=2` 被检查挡住，程序**没有执行** `a[2]`。若把检查删掉并读取 `a[2]`，那是错误反例，不应该拿实际运行一次的打印值当成语言规则。对 `INT_MAX + 1` 的有符号 `int` 加法也不能声称在 C11 中一定回绕；它同样可能触发 UB。无符号整数的模运算规则另见定宽整数课程。[ISO C N1570：6.5.6 加法、6.2.5 无符号范围](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)

## 逐步推演

### 列出可访问元素

`a` 的长度是 `sizeof a / sizeof a[0] = 2`；可访问下标满足 `0 <= index < 2`。

### 代入本次请求

本次 `index=2`，比较 `2 < 2` 为假，因此不进入数组读取分支。

### 选择可证明的结果

执行 `puts("index out of range")`，输出一行错误提示。这里能确定输出，是因为程序避开了越界访问。

### 对照错误写法

直接求值 `a[2]` 已超出数组对象的元素范围。即使某次机器上恰好读到 0 或程序没有崩溃，也不构成正确程序的证据。

## 面试回答

C 的 UB 是标准不再约束该错误操作的结果，典型例子有越界访问和有符号整数溢出；不能回答成“必定崩溃”或“必定回绕”。未指定行为是在允许选项中可选择，通常不用说明选择；实现定义行为要求实现记录其选择。解决办法是把有效输入条件写进代码，例如访问数组前先检验 `index < length`，而不是依赖一次运行碰巧成功。

## 选择题

C11 中 `int a[2]={7,9};`，若程序**直接求值** `a[2]`，哪项正确？

- A. 必须读到 0
- B. 必须立即崩溃
- C. 标准不规定这一错误访问的固定结果
- D. 结果仅由 `sizeof(int)` 决定

**答案：C。** `2` 已不是该数组的有效元素下标，这是 UB。A、B 都把可能的现象错当承诺；D 与边界规则无关。
