# 先来先服务与时间片轮转怎么手算

## 先规定题目条件

假设只有一个 CPU，任务 A、B、C 都在时刻 0 到达就绪队列，顺序为 A→B→C；各自需要的 CPU 时间分别为 5、2、1 个单位。任务期间没有 I/O 或新任务到达，暂不计上下文切换开销。**先来先服务**（First Come First Served，FCFS）选队首任务并让它一直运行到结束；**时间片轮转**（Round Robin，RR）每次最多运行一个时间片，未完成者回到就绪队列尾部。[OSTEP：Scheduling: Introduction](https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-sched.pdf)

“轮转”不是每个人都恰好用满时间片：B 只剩 1 单位时会提前结束，CPU 随即选下一个任务。

## 手算执行顺序

FCFS 时间线为 `A[0,5) → B[5,7) → C[7,8)`。方括号表示左端包含、右端不包含，所以 A 恰好运行 5 个单位。

RR 取时间片 2：开始队列 `[A,B,C]`；A 运行 `[0,2)` 后剩 3，排到队尾；B 运行 `[2,4)` 后完成；C 运行 `[4,5)` 后完成；A 再运行 `[5,7)` 后剩 1，最后运行 `[7,8)`。时间线为 `A[0,2) → B[2,4) → C[4,5) → A[5,7) → A[7,8)`。最后两个 A 段相邻，因为队列已没有别的就绪任务；真实实现未必会做一次无意义的切换。

| 策略 | 任务 | 首次运行 | 完成时刻 | 周转时间 | 等待时间 | 响应时间 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| FCFS | A / B / C | 0 / 5 / 7 | 5 / 7 / 8 | 5 / 7 / 8 | 0 / 5 / 7 | 0 / 5 / 7 |
| RR(2) | A / B / C | 0 / 2 / 4 | 8 / 4 / 5 | 8 / 4 / 5 | 3 / 2 / 4 | 0 / 2 / 4 |

周转时间 = 完成时刻 − 到达时刻；等待时间 = 周转时间 − 实际 CPU 服务时间，前提是题目没有 I/O 阻塞；响应时间 = 首次运行时刻 − 到达时刻。RR 让 B、C 更早首次运行，但本题 A 的完成从 5 延后到 8。平均等待时间 FCFS 为 4，RR 为 3；不能据此断言 RR 对任意任务集合都更优。

## 时间片不是越小越好

时间片短通常有利于缩短后来任务的首次响应等待，却会增加任务切换频率；切换本身要保存和恢复执行现场。在本课忽略切换开销才能直接把区间长度加成完成时间；真实系统必须考虑开销，而且调度策略还取决于优先级、到达时间、I/O 等。实验允许改时间片，观察队列与各任务指标如何变化。[OSTEP：Response Time and Round Robin](https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-sched.pdf)

## 面试回答

FCFS 按到达顺序运行到任务结束，实现简单，但长任务排在前面会拖延短任务。RR 给就绪任务轮流分配最多一个时间片，未完成者回队尾，能改善交互任务的首次响应；时间片太短会增加切换开销。手算时先画每段时间线，再由完成、首次运行、到达和服务时间计算周转、等待、响应；不能把这三个指标混为一谈。

## 常见误区

- **“时间片到就一定换到别人。”** 队列没有其他就绪任务时，同一任务可以继续。
- **“响应时间等于完成时间。”** 响应只看第一次被调度，周转才看完成。
- **“RR 必然使所有任务更早完成。”** 本题 A 从时刻 5 延后到 8。

## 选择题

沿用本课三个任务及 RR 时间片 2，任务 C 的响应时间是多少？

- A. 1
- B. 2
- C. 4
- D. 5

**答案：C。** C 在时刻 0 到达，时刻 4 首次运行，因此响应时间为 4；时刻 5 是它的完成时刻，不是首次响应。
