# 进程与线程：资源放在哪里，指令由谁执行

## 面试回答

在常见的现代操作系统（Operating System，OS）中，进程（Process）是资源管理和隔离的重要单位，线程（Thread）是进程内的执行流。同一进程的线程共享虚拟地址空间及很多资源，但各自保留程序计数器（Program Counter，PC）、寄存器上下文和调用栈。常见内核调度内核线程，用户态运行时也可以在其上调度其他执行单元。不同进程通常通过进程间通信（Inter-Process Communication，IPC）协作；创建、切换与通信成本必须结合实现和工作负载判断。

## 从正在运行的程序开始

磁盘上的程序文件是一份静态内容。运行它时，操作系统需要安排地址空间、代码和数据、打开的资源，以及实际执行指令的线程。

“地址空间”（Address Space）可以先理解为一个进程能够使用的一套地址。普通程序通常使用虚拟地址；相同的虚拟地址，在两个不同进程中可以映射到不同的物理存储，不能仅凭地址数字相同就认为它们共享数据。

进程描述“这组资源和隔离边界属于谁”；线程描述“当前执行到哪条指令、下一步怎样继续”。同一个进程可以拥有多个执行流。[Microsoft 进程与线程说明](https://learn.microsoft.com/en-us/windows/win32/procthread/about-processes-and-threads)

## 哪些共享，哪些各自保存

| 内容 | 同一进程的多个线程 | 为什么 |
| --- | --- | --- |
| 虚拟地址空间 | 共享 | 可以访问同一份程序数据 |
| 全局数据与堆中对象 | 通常共享、可共同访问 | 线程之间可以传递对象的地址 |
| 打开的文件等进程资源 | 通常共享 | 具体资源规则由系统规定 |
| 程序计数器与寄存器上下文 | 各自保存 | 每个线程的执行位置不同 |
| 调用栈 | 各自维护 | 函数调用层次与局部状态不同 |
| 线程局部存储（Thread-Local Storage，TLS） | 各自具有独立实例 | 同名变量可以保存各线程自己的值 |

“每个线程有自己的栈”描述的是分配与使用方式，不意味着栈位于完全隔离的地址空间。线程栈仍在进程的地址空间中；把有效栈对象的地址交给另一个线程后，还必须考虑生命周期和同步。

不同进程也并非绝对不能共享数据：共享内存可以把一块存储映射进多个进程。共享的范围需要明确安排，访问规则仍然需要协调。

## 一步一步看两个线程做事

假设一个程序有线程 A 和线程 B：A 接收请求，B 整理已经收到的数据。

1. A 开始运行，中央处理器（Central Processing Unit，CPU）使用 A 的寄存器和执行位置。
2. A 等待网络数据，在阻塞式接口下可能进入等待状态。
3. 调度器选择就绪的 B，恢复 B 的执行上下文。
4. B 继续从上次停下的位置工作，不是重新运行整个函数。
5. 网络数据到达后，A 变为可运行，等待调度器再次安排。

上面只是一个可能的执行顺序。系统不会承诺每次都按 A、B、A、B 固定轮流执行，也不是所有输入输出（Input/Output，I/O）接口都会阻塞调用线程。

保存旧线程、恢复新线程执行状态的过程称为上下文切换（Context Switch）。同一进程内的线程切换通常不需要更换进程地址空间，但仍然有调度、寄存器和缓存等成本，不能说“切换免费”。

## 就绪与阻塞为什么不同

先使用单个硬件执行上下文的三状态教学模型；现代系统还会细分状态，名称不一定完全相同。

| 当前状态 | 含义 | 哪件事会改变它 |
| --- | --- | --- |
| 就绪（Ready） | 具备运行条件，正在等待 CPU | 被调度后进入运行 |
| 运行（Running） | 当前执行指令 | 时间片到期可回到就绪；等待事件可进入阻塞 |
| 阻塞（Blocked） | 缺少继续执行所需的事件或资源 | 等待的条件满足后通常转为就绪 |

若 A 等待网络而 B 正在运行，网络数据到达只让 A 获得运行资格；A 不一定立即抢占 B。阻塞也不是“正在 CPU 上循环等待”，后者通常称为忙等。

进程还有创建和退出阶段。教材中的进程控制块（Process Control Block，PCB）用于描述进程标识、状态、资源等管理信息；实际系统会把部分执行上下文放在线程相关结构中。不能把 PCB 当成程序机器码本身。

一次系统调用只是请求内核服务，不必然切换到另一个线程。判断是否发生上下文切换，要看执行主体是否改变，而不只是看权限是否改变。

## 并发为什么不一定并行

**并发（Concurrency）**表示多个任务在一段时间内交替或重叠推进；**并行（Parallelism）**表示多个任务在同一时刻实际执行。

一个 CPU 核心也可以通过切换线程实现并发。多核提供并行执行的硬件条件，但能否用上多个核，还受任务依赖、运行时机制和调度影响。线程数量增加，不等于速度一定提高。

## 从共享资源看同步的必要性

本课实验将两次加一拆成读取、计算和写回，演示线程如何访问共同数据。若 A、B 都先读到 `0`，随后都写回 `1`，教学模型里的最终值就是 `1`。每条线程保留自己的临时变量 `local`，但都访问同一个共享计数器 `count`；启用同一把锁后，完整读改写被互斥保护。

这里假设每次读写完整发生，并按显示的顺序执行；它不是操作系统调度保证。真实 C/C++ 普通变量的未同步并发读写还可能构成数据竞争，结果不能被限定为 `1` 或 `2`。

详细的丢失更新过程、临界区与加锁范围见[互斥与临界区](./synchronization.md)。本课先记住：线程能够共享数据，不表示共享访问自动正确。

## 为什么还要用多进程

共享内存方便，但同一进程中一个线程的不当内存写入可能破坏其他线程使用的数据。进程边界提供更强的隔离，适合希望限制故障影响范围的场景。

不同进程可以使用管道、套接字、共享内存等方式协作。通信方式不同，数据是否复制、如何同步、延迟多少都会不同，不能简单断言“进程通信一定很慢”。

选择进程或线程时，可以依次说明：需要多强的故障隔离、要共享多少状态、工作主要在计算还是等待、运行时如何安排执行，以及创建和通信成本。

## 常见误解

- **“进程才执行代码，线程只是辅助。”** 在线程模型下，具体被调度执行的是线程，进程提供它依赖的资源。
- **“线程共享所有状态。”** 共享地址空间不等于共享同一份寄存器、执行位置和调用栈。
- **“有两条线程就一定在两颗核上同时运行。”** 能否并行取决于硬件、运行时、就绪状态和调度。
- **“只要一行代码就不会被打断。”** 一行源码可能对应多个操作，原子性必须来自明确的语言或平台保证。

## 选择题

关于常见操作系统中的进程与线程，下列哪一项正确？

- A. 同一进程的所有线程共用同一个程序计数器
- B. 线程各有调用栈，因此线程间无法访问共同的堆对象
- C. 同一进程的线程共享地址空间，但各自保存执行上下文
- D. 只要创建更多线程，CPU 密集任务就一定更快

**答案：C。** A 会使不同线程无法保存各自的执行位置；B 把栈的独立使用误解为地址空间隔离；D 忽略了核数、同步、运行时与调度成本。共享地址空间与独立执行上下文可以同时成立。

## 开放题

**网络数据到达后，等待它的线程为什么不一定立即开始运行？**

数据到达解决了等待条件，通常使线程由阻塞变为就绪。它何时实际运行，还取决于可用的硬件执行上下文、优先级、调度策略和其他任务。就绪是一种资格，运行才表示正在获得处理器时间。

**一个进程和一个线程能直接比较谁更快吗？**

问题需要具体化：比较创建、切换、通信还是整个任务耗时？同一进程的线程共享地址空间通常便于协作，但共享锁竞争也可能降低性能。必须先确定场景，再测量相同工作量下的表现。
