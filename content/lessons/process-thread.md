# 进程与线程：资源放在哪里，指令由谁执行

## 面试回答

在常见的现代操作系统中，进程是资源管理和隔离的重要单位，线程是进程内可被调度的执行流。同一进程的线程共享虚拟地址空间及很多系统资源，但各自保留程序计数器、寄存器上下文和栈。共享数据让协作方便，也带来同步问题。不同进程通常通过进程间通信交换数据，隔离性更强；实际开销和并行能力还取决于操作系统、运行时及工作负载。

## 从正在运行的程序开始

磁盘上的程序文件是一份静态内容。运行它时，操作系统需要安排地址空间、代码和数据、打开的资源，以及实际执行指令的线程。

“地址空间”可以先理解为一个进程能够使用的一套虚拟地址。相同的虚拟地址，在两个不同进程中通常可以映射到不同的数据，不能仅凭地址数字相同就认为它们正在共享内存。

进程描述“这组资源和隔离边界属于谁”；线程描述“当前执行到哪条指令、下一步怎样继续”。同一个进程可以拥有多个执行流。[Microsoft 进程与线程说明](https://learn.microsoft.com/en-us/windows/win32/procthread/about-processes-and-threads)

## 哪些共享，哪些各自保存

| 内容 | 同一进程的多个线程 | 为什么 |
| --- | --- | --- |
| 虚拟地址空间 | 共享 | 可以访问同一份程序数据 |
| 全局数据与堆中对象 | 通常共享、可共同访问 | 线程之间可以传递对象的地址 |
| 打开的文件等进程资源 | 通常共享 | 具体资源规则由系统规定 |
| 程序计数器与寄存器上下文 | 各自保存 | 每个线程的执行位置不同 |
| 调用栈 | 各自维护 | 函数调用层次与局部状态不同 |
| 线程局部存储 | 各自具有独立实例 | 同名变量可以保存各线程自己的值 |

“每个线程有自己的栈”描述的是分配与使用方式，不意味着栈位于完全隔离的地址空间。线程栈仍在进程的地址空间中；把有效栈对象的地址交给另一个线程后，还必须考虑生命周期和同步。

不同进程也并非绝对不能共享数据：共享内存可以把一块存储映射进多个进程。共享的范围需要明确安排，访问规则仍然需要协调。

## 一步一步看两个线程做事

假设一个程序有线程 A 和线程 B：A 接收请求，B 整理已经收到的数据。

1. A 开始运行，CPU 使用 A 的寄存器和执行位置。
2. A 等待网络数据，在阻塞式接口下可能进入等待状态。
3. 调度器选择就绪的 B，恢复 B 的执行上下文。
4. B 继续从上次停下的位置工作，不是重新运行整个函数。
5. 网络数据到达后，A 变为可运行，等待调度器再次安排。

上面只是一个可能的执行顺序。系统不会承诺每次都按 A、B、A、B 固定轮流执行，也不是所有 I/O 接口都会阻塞调用线程。

保存旧线程、恢复新线程执行状态的过程称为上下文切换。同一进程内的线程切换通常不需要更换进程地址空间，但仍然有调度、寄存器和缓存等成本，不能说“切换免费”。

## 并发为什么不一定并行

**并发**表示多个任务在一段时间内交替或重叠推进；**并行**表示多个任务在同一时刻实际执行。

一个 CPU 核心也可以通过切换线程实现并发。多核提供并行执行的硬件条件，但能否用上多个核，还受任务依赖、运行时机制和调度影响。线程数量增加，不等于速度一定提高。

## 共享计数器为什么会少加一次

假设共享计数器最初为 `0`，两个线程都要做一次加一。为了观察问题，先把加一拆成三步：读取、计算、写回。

下面是一个**教学执行模型**：单次读写完整发生，并按表格顺序交错。它不承诺任何语言中的未同步代码一定产生同样结果。

| 步骤 | 线程 A | 线程 B | 共享 counter |
| --- | --- | --- | --- |
| 1 | 读到 0 | 尚未读取 | 0 |
| 2 | 保留读到的 0 | 也读到 0 | 0 |
| 3 | 算出 1 | 保留读到的 0 | 0 |
| 4 | 暂未写回 | 算出 1 | 0 |
| 5 | 写回 1 | 暂未写回 | 1 |
| 6 | 已完成 | 写回 1 | 1 |

两个线程都“加过一”，最终却是 `1`，因为后写入的结果覆盖了先前结果。这叫丢失更新，问题出在整个“读、改、写”没有作为一个不可分割的整体执行。

一种解决办法是用同一把互斥锁保护这整个操作，其他需要受保护的访问也遵守同一同步规则。另一个办法是使用语言或平台提供的原子加法，不能只把普通变量改个名字就认为它具有原子性。

```text
acquire(mutex)
counter = counter + 1
release(mutex)
```

这是伪代码，不是可直接运行的程序。真实代码还需要处理异常时释放锁，并遵守相应语言的内存模型。例如 C/C++ 中，对同一普通变量未同步地并发读写可能形成数据竞争并导致未定义行为，不能把它的结果限定为 `1` 或 `2`。

## 为什么还要用多进程

共享内存方便，但同一进程中一个线程的不当内存写入可能破坏其他线程使用的数据。进程边界提供更强的隔离，适合希望限制故障影响范围的场景。

不同进程可以使用管道、套接字、共享内存等方式协作。通信方式不同，数据是否复制、如何同步、延迟多少都会不同，不能简单断言“进程通信一定很慢”。

选择进程或线程时，可以依次说明：需要多强的故障隔离、要共享多少状态、工作主要在计算还是等待、运行时如何安排执行，以及创建和通信成本。[Oracle 进程与线程教程](https://docs.oracle.com/javase/tutorial/essential/concurrency/procthread.html)

## 常见误解

- **“进程才执行代码，线程只是辅助。”** 在线程模型下，具体被调度执行的是线程，进程提供它依赖的资源。
- **“线程共享所有状态。”** 共享地址空间不等于共享同一份寄存器、执行位置和调用栈。
- **“有两条线程就一定在两颗核上同时运行。”** 能否并行取决于硬件、运行时、就绪状态和调度。
- **“只要一行代码就不会被打断。”** 一行源码可能对应多个操作，原子性必须来自明确的语言或平台保证。

## 选择题

关于常见操作系统中的进程与线程，下列哪一项正确？

- A. 同一进程的所有线程共用同一个程序计数器
- B. 线程各有调用栈，因此线程间无法访问共同的堆对象
- C. 同一进程的线程共享地址空间，但各自保存执行上下文
- D. 只要创建更多线程，CPU 密集任务就一定更快

**答案：C。** A 会使不同线程无法保存各自的执行位置；B 把栈的独立使用误解为地址空间隔离；D 忽略了核数、同步、运行时与调度成本。共享地址空间与独立执行上下文可以同时成立。

## 开放题

**为什么给计数器加锁后结果正确了，程序却可能变慢？**

锁让同一时刻进入临界区的线程受到限制。如果大量时间都花在同一把锁保护的区域里，工作就会被串行化，还可能产生等待与调度成本。解释改进方向时，应先减少共享写入或缩短临界区，再依据测量考虑分片计数、原子操作等方案；移除必要同步不是性能优化。
