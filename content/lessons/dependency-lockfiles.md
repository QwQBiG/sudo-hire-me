# 昨天能构建，今天同样源码却失败了？

## 依赖图也是构建输入

项目直接使用库 A，A 又依赖库 B，B 还依赖库 C。你只在项目声明里写下 A，并不意味着构建只受 A 影响；B、C 是**传递依赖**（Transitive Dependencies）。如果声明允许一个版本范围，而不同时间解析到的新版本不同，相同项目源码也可能面对不同的依赖行为。

以 Rust 的 Cargo 为例，`Cargo.toml` 声明包和版本要求，`Cargo.lock` 记录一次解析得到的具体依赖图与版本。锁文件帮助不同机器和时间选取同一批依赖版本，但不自动锁定编译器、系统库、构建选项或运行环境。[Cargo Book：Lockfile](https://doc.rust-lang.org/cargo/faq.html#why-have-cargolock-in-version-control)

## 逐步推演

### 第一步：把直接依赖与间接依赖画开

假设项目 P 声明需要 A 的某个兼容版本；本次解析选择 A 1.4.2，而 A 依赖 B 2.1.0，B 又依赖 C 3.0.1：

```text
P -> A 1.4.2 -> B 2.1.0 -> C 3.0.1
```

P 的作者没有直接调用 C，也可能受 C 的构建失败、安全问题或行为变化影响。排查“我没改这份代码为何坏了”时，先比较实际依赖图，而不只比较项目源码。真实解析规则还可能涉及多个版本并存、平台条件和特性选择，本图只展示单一路径。

### 第二步：声明范围与解析结果回答不同问题

声明中的版本要求回答“哪些版本**允许被选择**”；锁文件回答“这次**实际选择了谁**”。例如声明仍允许 A 1.4 系列，而锁文件把 A 固定在 1.4.2，之后发布 1.4.3 通常不会让已有锁文件无缘无故自动改成 1.4.3。主动更新依赖或修改要求时，解析结果和锁文件才可能变化。[Cargo Book：Dependency Resolution](https://doc.rust-lang.org/cargo/reference/resolver.html#lock-file)

不能只说“我已经固定 A”，却忽略 A 的传递依赖；应检查锁住的是整张实际依赖图，还是只在声明里写了一个大致范围。

### 第三步：解释一次失败为何只发生在某台机器

若同一提交在开发机通过、持续集成（Continuous Integration，CI）失败，可能是 CI 未使用已有锁文件、工具链不同、系统依赖缺失，或平台条件触发了另一条代码路径。先核对源码提交、锁文件、工具链和构建命令；不要直接认定“锁文件没用”。

对 Cargo 项目，`--locked` 可以要求构建不要悄悄更新锁文件，若解析必须改变则报错；这有利于发现依赖状态漂移，但仍不意味着产物字节完全相同。[Cargo Book：Dependency Resolution](https://doc.rust-lang.org/cargo/reference/resolver.html#lock-file)

### 第四步：解释锁文件的适用边界

应用项目通常希望部署和 CI 复用已经检查过的依赖图。作为库发布时，使用者的依赖解析还要满足他们自己的约束；不能假定库仓库里的锁文件会强制所有下游项目使用相同版本。不同生态的文件名、发布约定和锁定行为也不同，讨论时应说清所用工具与版本。[Cargo Book：为什么提交 Cargo.lock](https://doc.rust-lang.org/cargo/faq.html#why-have-cargolock-in-version-control)

## 面试回答

依赖声明描述允许的版本要求，锁文件记录实际解析出的直接和传递依赖版本，帮助开发机与 CI 在同一依赖图上工作。它不能单独固定编译器、系统库、配置或平台，因此不自动保证字节级相同产物。遇到“同源代码不同结果”，我会一起核对提交、锁文件、工具链、构建命令和环境，而不是只看直接依赖。

## 更新依赖时需要验证什么

查看哪些直接或传递依赖版本发生变化，运行测试与构建，并留意新版本的兼容性和安全公告。锁文件让更新变得显式和可审查，但一直不更新也不是安全策略。回退时要确认实际产物与依赖图一同回到预期状态。

## 常见误区

- **“项目只依赖声明中的一个库。”** 传递依赖也是构建输入。
- **“版本要求和锁文件是同一份信息。”** 前者是允许范围，后者是已解析选择。
- **“有锁文件就保证各平台二进制逐字节相同。”** 工具链和环境仍会影响结果。
- **“库里的锁文件能强制所有使用者的依赖版本。”** 下游项目有自己的解析过程。

## 选择题

项目源码不变，但未使用已有锁文件时一次新安装解析出了更新的传递依赖。哪项最准确？

- A. 源码没变，任何依赖版本都不可能变化。
- B. 传递依赖也可能改变构建行为；应比较实际解析图并用锁文件控制已验证的版本组合。
- C. 锁文件自动固定编译器和操作系统。
- D. 只要把直接依赖名写进文档，就不需要检查版本。

**答案：B。** A、D 忽略传递依赖和解析结果，C 夸大锁文件范围。
