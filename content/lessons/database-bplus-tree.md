# B+ 树索引怎样定位单值和扫描范围

## 先画出这棵小树

**B+ 树**（B+ Tree）是常见的磁盘索引组织思想：内部节点保存引导查找的分隔键与子节点指针，数据条目集中在叶节点；叶节点按键有序，常可顺序访问相邻叶。真实数据库对页布局、前缀压缩、覆盖信息、并发控制等有不同实现，本课只用三片叶子的概念模型，不能把画面当成任一引擎的精确磁盘格式。[PostgreSQL：B-Tree Indexes](https://www.postgresql.org/docs/current/btree.html)

根节点分隔键为 `[20,40]`，含义约定为：`key < 20` 走左叶、`20 ≤ key < 40` 走中叶、`key ≥ 40` 走右叶。叶内容分别是 `[5,10,15]`、`[20,25,30]`、`[40,45,50]`；相邻叶按左到右链接。

## 动手查两个问题

查 `25`：在根节点判断 `20 ≤ 25 < 40`，进入中叶；中叶查得 `25`。查 `27` 也到中叶，但叶中不存在，返回未命中。范围查 `[20,45]`：先用下界 20 定位中叶，读出 `20,25,30`，再沿叶间顺序读右叶的 `40,45`；遇到 50 已超过上界，停止。实验会点亮实际经过的根、叶与结果键。

范围扫描能顺序经过相邻条目，但不意味着任意范围查询都一定走索引：若范围覆盖大部分表，优化器可能选择全表扫描；若查询还要取索引外列，还涉及回表等成本。[SQLite：Query Planner](https://www.sqlite.org/queryplanner.html)

## 面试回答

B+ 树用内部节点的分隔键把查找引向一片叶，叶节点保存有序条目；等值查找到叶后定位目标键，范围查询先定位下界，再沿有序叶条目向后扫描到上界。它适合范围访问，但“有索引就必用”是错误的，优化器会比较成本。具体数据库的索引页与叶链接细节要看实现。

## 常见误区

- **“根节点的 20、40 就是本课全部数据行。”** 它们是路径分隔键；结果从叶条目取。
- **“范围查询需为每个值都重新从根走一遍。”** 可从起始位置继续扫描有序叶。
- **“B+ 树形状始终固定。”** 插入、删除可能导致节点分裂或合并；本实验固定树形只演示查找。

## 选择题

按本课分隔规则，等值查找 45 首先进入哪片叶？

- A. 左叶 `[5,10,15]`
- B. 中叶 `[20,25,30]`
- C. 右叶 `[40,45,50]`
- D. 三片叶都要遍历

**答案：C。** 45 不小于根节点分隔值 40，按本课“等于分隔值走右侧”的规则进入右叶，再在 `[40,45,50]` 中比较。左叶和中叶的范围都不包含 45，等值查找也不必遍历三片叶。
