# 二进制与补码：同一串位怎样表示不同的数

## 面试回答

二进制每一位只有 `0` 和 `1`，数值取决于各位的权重。8 位无符号整数范围是 `0..255`；8 位补码有符号整数范围是 `-128..127`。补码中，最高位权重为 `-128`，其余位仍是正权重。求 `-5` 的 8 位补码，可以把 `5` 的位模式逐位取反再加一，得到 `11111011`。解释一个位模式时必须同时说明位宽和有无符号。

## 先理解“位”和“权重”

十进制的 `305` 表示 `3 × 100 + 0 × 10 + 5 × 1`。二进制采用同样的计数思路，只是每进一位乘以 `2`。

从右向左，8 位无符号二进制的权重依次是 `1、2、4、8、16、32、64、128`。某位为 `1` 就计入它的权重，为 `0` 就不计入。

| 位模式 | 展开 | 十进制数值 |
| --- | --- | --- |
| `00000101` | `4 + 1` | 5 |
| `00001101` | `8 + 4 + 1` | 13 |
| `10000000` | `128` | 128 |
| `11111111` | `128 + 64 + 32 + 16 + 8 + 4 + 2 + 1` | 255 |

8 个二进制位一共有 `2⁸ = 256` 种不同组合。无符号解释把它们分配给 `0..255`，因此最大值为 `2⁸ - 1`，不是 `256`。

## 负数怎样放进相同的 8 位

位模式本身没有自动附带“正负号”。补码是一种解释规则：把最高位的权重改成负值。

对于 8 位补码，权重从左到右是 `-128、64、32、16、8、4、2、1`。例如：

`11111011 = -128 + 64 + 32 + 16 + 8 + 0 + 2 + 1 = -5`

这也解释了范围：最小值是 `10000000`，即 `-128`；最大值是 `01111111`，即 `127`。最高位为 `0` 的 128 种模式分给 `0..127`，最高位为 `1` 的 128 种模式分给 `-128..-1`。

负数比正数多一个，是因为非负一侧还要包含 `0`。补码只有一个零，即 `00000000`。Java 的 `byte` 就明确采用 8 位有符号补码，范围为 `-128..127`。[Java 语言规范](https://docs.oracle.com/javase/specs/jls/se21/html/jls-4.html#jls-4.2.1)

## 一步一步求 -5 的补码

先固定为 **8 位**，再执行下面的操作；没有位宽，“逐位取反”就没有明确的终止位置。

| 步骤 | 操作 | 结果 |
| --- | --- | --- |
| 1 | 写出正数 `5` 的 8 位表示 | `00000101` |
| 2 | 逐位取反，`0` 与 `1` 互换 | `11111010` |
| 3 | 在该位模式上加 `1` | `11111011` |
| 4 | 按补码权重检验 | `-128 + 123 = -5` |

也可以用另一条思路：8 位无符号模式 `251` 与 `-5` 相差 `256`。因此 `256 - 5 = 251` 对应的位模式，正好就是 `-5` 的 8 位补码。

## 为什么取反再加一有效

对 8 位位模式，逐位取反等于用 `255` 减去原来的无符号值。再加一，就得到 `256 - x`。

在只保留低 8 位的加法中，超出的 `256` 被舍去。因此 `x + (256 - x)` 留下零。这让减去 `x` 可以转换成加上它的补码位模式。

例如 `7 + (-5)`：先把位模式当作无符号数相加，`7 + 251 = 258`；保留低 8 位等于 `258 - 256 = 2`，最后得到 `00000010`。这个例子没有超出有符号结果范围。

这里描述的是固定 8 位的位模式计算。编程语言如何处理溢出、是否提升为更宽类型，需要另外查看语言规则。

## 实验代码

JavaScript 的普通 `Number` 不是 8 位整数。下面通过 `Uint8Array` 和 `Int8Array` 查看同一个字节，分别采用无符号和有符号解释。

```javascript
const unsigned = new Uint8Array([0b11111011]);
const signed = new Int8Array(unsigned.buffer);

console.log(unsigned[0]);
console.log(signed[0]);
console.log(unsigned[0].toString(2).padStart(8, "0"));
```

```text
251
-5
11111011
```

字节没有改变，改变的是读取方式。两种类型都使用 8 位，但给最高位分配了不同的权重。[JavaScript TypedArray 文档](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypedArray)

## 溢出与进位不是同一件事

`01111111 + 00000001` 得到低 8 位 `10000000`。按无符号数解释是 `127 + 1 = 128`，可以表示；按有符号补码解释，数学结果 `128` 超过上限 `127`，发生有符号溢出。

所以，判断是否溢出，要看**数学结果是否超出所选类型的可表示范围**。仅观察有没有最高位之外的进位，不足以判断有符号溢出。

不要根据这个位模式例子断言“所有语言的有符号整数溢出都会回绕”。例如 C++ 的普通有符号整数算术溢出属于未定义行为；本节的字节查看示例没有执行这种操作。[C++ 表达式规则](https://eel.is/c++draft/expr.pre)

## 常见误解

- **“`11111011` 就是负数。”** 按无符号解释是 `251`，按 8 位补码解释才是 `-5`。
- **“最高位只表示正负，其余七位表示绝对值。”** 那是符号与数值分开的一类表示思路；补码中最高位参与带负权重的求和。
- **“取反就能得到负数。”** 本例 `11111010` 的补码数值是 `-6`，还需要加一才得到 `-5`。
- **“扩展位宽时都在左边补零。”** 保持补码数值不变要进行符号扩展；`-5` 扩成 16 位是 `1111111111111011`。

## 选择题

位模式 `10000000` 在 8 位无符号整数和 8 位补码有符号整数中，分别表示什么？

- A. `128` 和 `-128`
- B. `128` 和 `-0`
- C. `256` 和 `-128`
- D. `-128` 和 `128`

**答案：A。** 无符号最高位权重为 `128`，补码最高位权重为 `-128`。B 把补码误当成符号与绝对值分开的表示；C 把 8 位的组合数量误当成某个位的权重；D 颠倒了两种解释规则。

## 开放题

**为什么 8 位补码的 `-128` 没有对应的可表示正数？**

8 位只有 256 种模式，补码把它们分配给 `-128..127`。数学上的 `128` 超出了这个范围。要完整表示 `-(-128)` 的数学结果，需要先扩到至少 9 位，再取相反数；在具体语言里还要考虑表达式是否发生整数提升。
