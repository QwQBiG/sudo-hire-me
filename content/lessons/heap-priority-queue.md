# 堆与优先队列

## 面试回答

优先队列（Priority Queue）总是先取出优先级最高的元素；最小堆（Min-Heap）把键最小的元素放在根节点。二叉堆通常用数组保存完全二叉树，满足每个父节点的键不大于子节点。取最小值是 O(1)，插入和删除最小值要沿树高调整，为 O(log n)；堆不保证数组整体有序，也不天然保证相同优先级的稳定先后。

## 从数组看到树

最小堆可以保存为 `[2, 4, 3, 8, 6, 5, 7]`。下标从 0 开始，位置 i 的左、右孩子分别在 `2i+1` 和 `2i+2`；非根节点的父亲在 `⌊(i−1)/2⌋`。

```text
           2(0)
       /          \
     4(1)        3(2)
    /   \        /   \
  8(3)  6(4)   5(5)  7(6)
```

括号是数组下标。结构是**完全二叉树**：除最后一层外每层满，最后一层从左到右填入。堆序只要求父节点不大于直接孩子，例如根的两个孩子是 4 和 3，仍然合法；不能推断左子树中所有元素小于右子树。[Python 官方文档：Heap Queue Algorithm](https://docs.python.org/3/library/heapq.html)

## 取走最小值，为什么要下沉

删除根 `2` 后不能直接把数组整体左移：那样既没保留完全二叉树的原数组映射，也需要线性搬移。先用最后的 `7` 填根，缩短数组，再与两个孩子中较小者交换，直到父子关系恢复：

| 步骤 | 数组 | 观察 |
| --- | --- | --- |
| 初始 | `[2,4,3,8,6,5,7]` | 根 2 是最小值 |
| 移走 2，末尾 7 补根 | `[7,4,3,8,6,5]` | 7 大于两个孩子 |
| 7 与较小孩子 3 交换 | `[3,4,7,8,6,5]` | 7 仍大于自己的孩子 5 |
| 7 与 5 交换 | `[3,4,5,8,6,7]` | 到达叶子，堆序恢复 |

每次只沿一条父子路径下沉。完全二叉树有 n 个节点时高度为 Θ(log n)，所以删除堆顶的最坏时间是 O(log n)，额外空间可为 O(1)。插入则把元素放在数组末尾并向上比较、交换，称为上浮（Sift Up），同样是 O(log n)。

## 堆不等于排好序的数组

在 `[2,4,3,8,6,5,7]` 中，`4` 出现在 `3` 前面，数组并非升序；只有根必为全局最小。若要依次得到所有元素，需要反复删除堆顶。直接读取最小值不应与删除最小值混为一谈：前者 O(1)，后者要修复堆序。对一批已有元素自底向上建堆可在 O(n) 时间完成，不等同于逐个插入的 O(n log n) 上界。[Python 官方文档：Heap Queue Algorithm](https://docs.python.org/3/library/heapq.html)

堆常用于任务调度、前 k 个元素、最短路径等需要反复取最小值的场景。但优先级相同的两个任务未必按进入顺序出队；需要稳定行为时，可以把单调递增的到达序号作为第二比较键。

## 在实验里检查

先从根看父子不变量，再逐步取走最小值。每步查看树和底部数组的同一个下标，观察为什么必须选择**较小的子节点**交换。切换另一组初始堆，自己先预测下一步，再点击验证。比较计数仅属于这段具体模拟，并非耗时测量。

## 常见误区

- **“最小堆的数组是升序的。”** 堆只保证局部父子关系，非根元素的全局先后没有保证。
- **“孩子下标是 2i 和 2i+1。”** 这是从 1 开始编号时常见的写法；本课从 0 开始，必须加 1 和加 2。
- **“删除根后拿任意元素补上即可。”** 末尾元素补根保持完全二叉树形状，然后仍须下沉修复堆序。

## 选择题

对下标从 0 开始、数组表示的二叉最小堆，删除根后的第一步通常是什么？

- A. 直接返回下标 1，数组不用变化
- B. 用数组末尾元素补根，再向下恢复堆序
- C. 把所有元素整体左移一格，结束
- D. 交换根的两个孩子，结束

**答案：B。** 末尾补根保留完全二叉树的存储形状，之后沿较小孩子方向下沉。A 只适用于读取根的值，不能完成删除；C、D 都没有保证父子堆序恢复。

## 面试追问

**为什么从 n/2 附近向上建堆是 O(n)，不是 O(n log n)？**

虽然单个靠近根的节点最多下沉 O(log n) 层，但绝大多数节点靠近叶子，只能下沉很少层。按节点高度把工作量相加，得到 O(n)；不能把每个节点都按最大高度计费。
