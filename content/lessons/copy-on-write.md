# fork 后为什么不立即复制全部内存

## 看起来复制了，物理内存可以先共享

写时复制（Copy-on-Write，COW）让两个独立地址空间在**只读阶段**暂时指向相同物理页；真正需要把某一方的修改与另一方隔开时，才为写入者准备可写的私有页。Linux 的 `fork()` 常用 COW 页实现，因此创建子进程不必立即复制父进程所有用户数据；仍有建立子进程任务结构和复制页表等成本，不是“零成本 fork”。[Linux manual：fork(2)](https://man7.org/linux/man-pages/man2/fork.2.html)

本例只讨论普通私有匿名页；显式共享映射、设备内存等可能有不同规则。页表项如何标记、哪个核心处理故障，依硬件和内核实现而定。

## 逐步推演

### P 原来拥有两页

父进程 P 的虚拟页 X 存着 `1`、页 Y 存着 `2`，分别在物理框 `F1`、`F2`。P 读 X 得 1，读 Y 得 2。此时没有子进程，也没有分离问题。

### fork 后 P、Q 都读相同内容

P 调用 `fork()` 得到子进程 Q。两者的**页表是各自的**，但有关 X、Y 的条目可以先指向同一物理框 F1、F2，并用受保护的写权限安排后续 COW。P 和 Q 读 X 都得 1，读 Y 都得 2；仅这两次读无需复制整页。不能因此说 P、Q 共享一个虚拟地址空间。

### Q 首次写 X，需要把这页分离

Q 执行 `X=9`。它对受保护的私有页写入会触发故障处理，内核确认这是一处可进行 COW 的合法写，给 Q 准备私有页（典型做法是复制 F1 的内容到新框 F3），再完成写入。此后 Q 的 X 为 9，P 的 X 仍为 1；两者的 Y 仍可共享 F2。**复制粒度是页，不是单个变量，也不是全部进程内存**。[Linux manual：fork(2)](https://man7.org/linux/man-pages/man2/fork.2.html)

### P 之后修改 Y

若 P 随后写 Y，系统同样要确保不改变 Q 看到的旧 Y。典型情况下分离 Y 页；若某页此时已只有一个引用者，实现也可能只恢复写权限而无需真的复制。最终 P、Q 各自的私有写入互不影响，但它们仍可通过明确的共享内存 IPC 机制另建共享区域。

## “页故障”不一定是程序写坏了

COW 写入常以页保护故障进入内核，再被内核合法处理并重新执行指令；**真正只读的映射**若不允许写入，则不能因为“也触发了故障”就自动变成可写页。先看映射语义，再判断故障能否修复。[Linux manual：mmap(2)](https://man7.org/linux/man-pages/man2/mmap.2.html)

## 面试回答

写时复制让 `fork` 后父子先共享私有映射对应的物理页，同时各有自己的虚拟地址空间和页表；读取可共享，某一方写入时通过受保护写入与缺页/保护故障处理，把需要修改的页分离，使另一方仍看到旧值。它避免立即复制全部数据，但页表和进程结构仍有开销；共享映射、只读权限及“只剩一个引用者”也不能与普通 COW 情形混为一谈。

## 常见误区

- **“fork 一返回就复制所有物理页。”** 普通私有页可先共享，修改时再分离。
- **“父子能读到相同数据，说明它们是同一个地址空间。”** 各自页表可暂时指向相同物理框。
- **“任何写故障都能通过 COW 修复。”** 对真正不可写的映射，写入仍是错误。

## 选择题

P fork 出 Q 后，Q 只写虚拟页 X，页 Y 一直无人写。最符合 COW 模型的是？

- A. X 和 Y 必须在 fork 当刻全部复制。
- B. Q 的 X 可分离成新物理页，Y 仍可被父子共享。
- C. Q 写 X 必然让 P 的 X 也变成新值。
- D. 每次读 Y 都必须再复制 Y。

**答案：B。** 按需分离的是发生私有写入的页；A、D 违背延迟复制，C 违背父子独立的私有内存语义。
